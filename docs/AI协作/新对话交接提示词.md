# 新对话交接提示词

## 1. 用途

当需要在新的 Codex / GPT 对话中继续 Float Clicker 项目时，可以把本文档中的提示词作为开场消息发送给新 AI。

目标：

- 让新 AI 先阅读项目文档和当前代码。
- 避免新 AI 不理解现有单点模式进度就直接大规模改动。
- 明确下一阶段开发边界。
- 保留“先分析、确认后再编码”的协作节奏。

## 2. 推荐开场提示词

```text
你现在接手 D:\code-my\float_clicker\float_clicker 项目。

请先阅读这些文档，理解当前进度，不要马上写代码：
- docs/需求文档/单点模式需求文档.md
- docs/需求文档/悬浮交互模式设计文档.md
- docs/需求文档/全局悬浮外观配置设计文档.md
- docs/需求文档/多点模式前置设计文档.md
- docs/验收清单/单点模式真机验收清单.md
- docs/调试问题/悬浮窗横竖屏贴边问题.md

当前项目状态：
- 单点模式已经基本稳定，已完成三态任务调度 idle/running/paused。
- 已完成普通/简洁/极简三种悬浮交互模式。
- 已完成 Overlay 组件拆分。
- 已完成全局悬浮外观配置，支持悬浮点位、控制条、独立控件分别缩放。
- 已处理 dispatchGesture 返回 false 的收尾。
- 已给 OverlayWindowHelper 加安全窗口操作封装。
- 单点模式真机验收基本通过。
- 现在准备进入多点模式开发。

开发原则：
- 先分阶段，不要大规模重写。
- 写代码前先检查 git status，避免覆盖我已有改动。
- 代码里加合适注释。
- 优先复用单点模式已经稳定的模型、悬浮交互、全局外观和异常收尾逻辑。
- 基础多点第一版只做多个固定点位按顺序点击。
- 长按、滑动、延迟、复杂连招先只在架构上预留，不进入第一版 UI。

请先输出：
1. 你理解的当前项目进度
2. 下一阶段推荐从哪里开始
3. 第一阶段应该改哪些文件
4. 风险点

等我确认后再编码。
```

## 3. 准备直接开发时的提示词

如果已经确认要开始多点模式第一阶段，可以使用下面这段：

```text
你现在接手 D:\code-my\float_clicker\float_clicker 项目。

请先快速阅读这些文档，确认项目现状：
- docs/需求文档/单点模式需求文档.md
- docs/需求文档/悬浮交互模式设计文档.md
- docs/需求文档/全局悬浮外观配置设计文档.md
- docs/需求文档/多点模式前置设计文档.md

然后开始第一阶段：Flutter 多点模型与持久化。

范围只包括：
- 新增 MultiPointTarget
- 新增 MultiPointSettings
- 新增多点持久化 store
- 保存/读取 multi_point.targets_json
- 增加对应测试

不要改 Android。
不要做多点页面。
不要实现高级连招 UI。

开发要求：
- 先检查 git status。
- 不覆盖已有未提交改动。
- 复用单点模式已有模型和持久化风格。
- 写代码时加合适注释。
- 完成后运行 flutter analyze 和 flutter test。
```

后续每进入一个新阶段，可以按下面模板补充提示词：

你现在接手 D:\code-my\float_clicker\float_clicker 项目。

请先阅读：
- docs/需求文档/单点模式需求文档.md

- [填写已完成内容]

- [填写本阶段范围]

不要做：
- [填写明确排除项]

## 5. 是否需要做成 Skill

当前建议：先放在 `docs/AI协作` 中，不急着做成 skill。

原因：

- 这类提示词强依赖当前项目进度，项目文档比 skill 更容易随需求同步更新。
- 新 AI 接手时需要的是项目上下文，而不是跨项目通用能力。
- 文档可以直接和需求、验收清单放在一起，版本管理更清晰。

适合做成 skill 的情况：

- 这套交接方式已经稳定，并且会在多个项目复用。
- 需要固定流程，例如“阅读文档 -> 检查 git -> 输出阶段计划 -> 等确认 -> 编码 -> 运行测试”。
- 希望新对话中只说一句“使用项目交接 skill”，AI 就能按固定流程工作。

如果后续要做成 skill，建议内容不要绑定 Float Clicker 的具体需求，而是抽象为：

```text
项目接手流程
- 读取项目文档
- 检查 git 状态
- 总结当前进度
- 识别下一阶段边界
- 输出改动文件和风险点
- 等用户确认后再编码
```

Float Clicker 的具体路径、当前进度和阶段目标仍然保留在项目文档中。

## 6. 维护建议

- 每完成一个大阶段后，更新本文档中的“当前项目状态”。
- 每新增重要需求文档或验收清单后，把路径加入推荐开场提示词。
- 如果某阶段已经完成，不要让提示词继续要求新 AI 从旧阶段开始。
- 如果要让新 AI 直接编码，必须明确“本阶段包含什么”和“本阶段不包含什么”。
