# 侧边栏控制面板实现任务清单

## Summary

- 本文承接《侧边栏控制面板最小实现计划》，进一步把第一轮侧边栏实现拆成可直接执行的任务清单。
- 本清单只覆盖“侧边栏只做全局控制壳”的最小实现，不扩大到 profile 列表、异常专门面板或 `P8` 能力。
- 本清单默认沿用当前推荐决策：入口文案使用“执行区”、空闲态显示已加载数量、不做“更多操作”、外部圆形执行控件继续保持可见。

## Scope

本轮任务清单包含：

- 收起态入口语义改造。
- 新增展开态侧边栏面板组件。
- 接入空闲态和运行中两种面板状态。
- 在运行中面板接入“停止当前任务”入口。
- 保持现有外部圆形执行控件、拖动、位置持久化、横竖屏校正和异常收尾不回退。

本轮任务清单不包含：

- 不实现侧边栏内 profile 列表。
- 不实现异常专门面板。
- 不新增 Flutter 页面设置项。
- 不新增 MethodChannel 协议，除非实现中确认无法复用当前状态。
- 不进入单点模式 UI 调整。

## Task Breakdown

### Task 1：收起态入口语义改造

目标：

- 把当前恢复入口从“展开执行控件组”的单一按钮语义，调整为“多配置执行区全局入口”的语义。

建议改动：

- 更新 `MultiProfileExecutionLauncherComponent` 的文案、`contentDescription` 和必要尺寸策略。
- 保留现有拖动、点击、位置持久化和贴边/可见区域校正逻辑。

验收要点：

- 收起态入口文案为“执行区”或等价短文案。
- 点击行为仍能展开执行区。
- 拖动与位置恢复无回退。

### Task 2：新增侧边栏面板组件

目标：

- 把展开态面板结构从 manager 内联逻辑中拆成独立组件，避免后续状态扩展继续堆在 manager 中。

建议改动：

- 新增一个独立组件，例如 `MultiProfileExecutionSidebarComponent`。
- 组件只负责：
  - 展示标题
  - 展示状态摘要
  - 展示说明文案
  - 展示按钮区
- 初版不承载 profile 列表，也不实现滚动内容。

验收要点：

- 组件可独立 show / update / remove。
- 尺寸和位置由 manager 管理，不自行持有复杂业务状态。

### Task 3：manager 接入空闲态面板

目标：

- 在不改变现有外部圆形执行控件链路的前提下，接入展开态空闲中面板。

建议改动：

- `MultiProfileExecutionOverlayManager` 增加“收起态入口 / 侧边栏面板 / 外部圆形执行控件”三者的显示协调。
- 空闲态面板展示：
  - `多配置执行区`
  - `空闲中`
  - `已加载 X 个配置`
  - `点击外部圆形执行控件可启动对应配置任务`
  - `收起`

验收要点：

- 展开后可见空闲态面板。
- 外部圆形执行控件继续保留。
- 收起后恢复到全局入口。

### Task 4：manager 接入运行中面板

目标：

- 让侧边栏在任务运行中承载“状态可见 + 当前配置名 + 停止入口”。

建议改动：

- 在 manager 中复用现有 `runningProfileId`、`taskStatus`、`profiles` 状态。
- 运行中面板展示：
  - `多配置执行区`
  - `运行中`
  - `当前配置：xxx`
  - 简短提示“当前仅支持停止任务”
  - `停止当前任务`
  - `收起`

验收要点：

- 点击外部执行控件启动任务后，展开侧边栏可见正确运行状态。
- 当前 profile 名称显示正确。

### Task 5：接入停止当前任务入口

目标：

- 侧边栏复用现有停止链路，不新增新的任务结束协议。

建议改动：

- manager 中将“停止当前任务”点击行为直接接到现有 `endActiveTask(...)` 或等价已验证链路。
- 保持停止后的 Toast、运行状态回落和单任务互斥语义一致。

验收要点：

- 从侧边栏点击停止后，任务安全结束。
- 面板回到空闲态。
- 再次点击外部圆形执行控件仍可启动任务。

### Task 6：最小回归与边界验证

目标：

- 确认第一轮侧边栏不会把 P7 已验证链路带回退。

建议验证：

- 收起 / 展开。
- 空闲 / 运行中状态切换。
- 停止当前任务。
- 无障碍断开与悬浮窗权限撤销后的异常收尾。
- 横竖屏切换后的入口和面板可见性。
- 单点模式最小回归。

## File Ownership Suggestion

为避免实现阶段改动面失控，建议按下列责任划分推进：

- `MultiProfileExecutionLauncherComponent.kt`
  - 只负责收起态入口语义和外观调整。
- `MultiProfileExecutionSidebarComponent.kt`（拟新增）
  - 只负责展开态面板的视图结构和按钮回调绑定。
- `MultiProfileExecutionOverlayManager.kt`
  - 负责状态编排、显示切换和现有任务链路接入。
- `MultiProfileExecutionOverlayModels.kt`
  - 仅在确实需要补充轻量 UI 状态模型时再修改，避免一开始就扩大模型层。
- `OverlayWindowHelper.kt`
  - 仅在组件尺寸、贴边或布局约束无法复用时才最小补充。

## Recommended Implementation Order

建议实现顺序严格按下面推进：

1. 先改收起态入口语义。
2. 再加独立侧边栏组件空壳。
3. 接入空闲态面板。
4. 接入运行中面板。
5. 最后接停止当前任务入口。
6. 全部完成后再做自动化验证和真机验收。

原因：

- 这样每一步都可以单独观察 UI 是否仍然可控。
- 若中途发现侧边栏方向不成立，可以在较小代价下停住，而不是已经牵连停止链路和状态同步。

## Checkpoints

建议实现中设置以下中间检查点：

### Checkpoint A

- 收起态入口语义已改。
- 侧边栏组件空壳已能显示。
- 尚未接入运行中状态和停止入口。

### Checkpoint B

- 空闲态与运行中面板都能展示。
- 当前 profile 名称能显示正确。
- 尚未接停止入口，或停止入口仍在本地开发中。

### Checkpoint C

- 停止入口已接入。
- 自动化验证通过。
- 可准备真机验收。

## Verification Checklist

自动化：

- `flutter analyze`
- `flutter test`
- `flutter build apk --debug`
- `git diff --check`

真机：

- 收起态入口显示“执行区”并可展开。
- 空闲态展示“已加载 X 个配置”。
- 点击某个外部圆形执行控件后，运行中面板展示当前配置名。
- 点击“停止当前任务”后任务结束并回到空闲态。
- 外部圆形执行控件继续可见且可再次启动。
- 无障碍断开 / 权限撤销异常收尾无回退。
- 横竖屏可见性无回退。
- 单点模式最小回归通过。

## Risks

- 当前 launcher 组件是单个按钮模型，若直接演进为“执行区”入口，可能会暴露尺寸或文本可读性问题。
- manager 目前主要围绕“按钮组 or launcher”切换，接入面板后显示层级会更复杂，需要避免出现窗口残留或状态切换闪动。
- 如果空闲态面板和外部圆形执行控件同时显示时过于拥挤，可能需要在真机上尽早观察布局密度。
