# 侧边栏控制面板交互方案草案

## Summary

- P7 已完成真实使用复验并建议正式收口，当前不再继续把自由横向停靠、防误触或暂停/继续等体验增强直接叠加到原分支上。
- 本轮只启动“侧边栏控制面板交互方案”草案，先明确交互目标、候选方向、兼容边界和是否需要最小原型。
- 本轮不改 Flutter、MethodChannel 或 Android Overlay 代码，不进入 `P8` 高级连招。

## Scope

- 包含：
  - 新建侧边栏控制面板交互方案草案文档。
  - 明确当前要解决的交互问题、适用场景和暂不做内容。
  - 给出至少两个候选方案并形成推荐方向。
  - 评估是否需要先做最小原型。
- 不包含：
  - 不实现侧边栏控制面板。
  - 不修改多配置执行区现有执行链路。
  - 不进入 `P8` 长按、滑动、延迟和高级连招。
  - 不引入多任务并行、暂停/继续控件、防误触完整配置或新的全局设置项。

## Plan

1. 复查 P7 收口后的阶段文档、协作记录和现有多配置执行设计文档，确认当前推荐下一步与阶段边界。
2. 基于真实使用反馈，归纳当前多配置执行区继续演进交互时的核心问题。
3. 为侧边栏控制面板整理至少两个候选方向，重点比较“只做全局控制壳”与“统一承载 profile 控制”。
4. 给出一个当前推荐方向，并明确该方向为什么更适合在 P7 收口后作为下一步。
5. 定义最小原型是否值得做，以及原型只验证哪些问题。
6. 更新阶段管理文档，记录“已进入侧边栏控制面板交互方案草案，但 `P8` 仍延期”的节奏说明。

- 已明确本轮只做方案，不做代码实现。

## Assumptions

- 当前最需要确认的是“交互壳层是否值得变化”，而不是立即重做已验证的多配置执行链路。
- 侧边栏若进入下一步，应先尽量复用 P7 已验证的单任务执行、异常收尾和恢复入口语义。
- `P8` 的动作能力入口依赖交互壳层方向，因此在侧边栏方案明确前继续延期更稳妥。
