# P7.3 执行模式与贴边展开按钮计划

## Summary

- 本文是 P7.3 计划草案，不代表功能已经实现。
- P7.2 已完成多配置执行控件显示、真实执行、位置持久化和异常收尾专项验收。
- P7.3 需要从“计划、实现、验收”重新分层：未实现能力只进入待实现计划，不进入真机测试项。
- 当前建议先做 P7.3.1 最小实现：执行控件组收起/展开入口；实现完成后再安排真机验收。

## Scope

P7.3.1 建议包含：

- 多点页现有“执行控件”卡片内提供全局执行控件组收起/展开入口。
- Android 收起时隐藏多个 profile 执行控件，只保留一个可恢复入口。
- 点击可恢复入口后，重新显示已加载配置执行控件。
- 任务运行中收起后，仍能通过可恢复入口找回当前运行控件，并点击该控件停止任务。
- 保持 P7.2.4 已验证的异常收尾行为不回退。

P7.3.1 不包含：

- 展开按钮位置持久化。
- 横竖屏可见区域校正专项。
- 暂停/继续控件。
- 多任务并行。
- 执行控件透明度、锁定位置、长按执行和二次确认。
- 控件分组、折叠面板滚动列表和复杂执行模式。
- P8 长按、滑动、延迟和高级连招。

## Plan

1. 先实现一个全局执行控件组收起状态，不做每个 profile 独立收起。
2. Flutter 侧新增最小执行 UI 状态，仅记录当前预览生命周期内控件组是否收起；关闭并重新开启预览时默认展开。
3. `show/updateMultiProfileExecutionOverlay` 向 Android 同步收起状态。
4. Android `MultiProfileExecutionOverlayManager` 展开时显示现有多个执行控件；收起时移除执行控件并显示一个固定默认位置的小型恢复按钮，视觉复用现有悬浮组件风格。
5. 可恢复入口点击后切回展开状态，并通过回调通知 Flutter 保存状态。
6. 如果没有任何可见 loaded profile，恢复入口随执行控件预览关闭或刷新结果一并消失；重新加载 profile 后再随预览显示。
7. `hide()`、悬浮窗权限撤销、无障碍断开继续完整移除所有窗口并结束活动任务。
8. P7.3.1 自动化验证通过后，再发真机验收模板。

## Acceptance Criteria

- 开启执行控件预览后，可以从 App 页面收起执行控件组。
- 收起后多个配置执行控件不再显示，并保留一个明确可见的恢复入口。
- 点击恢复入口后，已加载配置执行控件重新显示，原有 profile 绑定执行能力不变。
- 关闭并重新开启执行控件预览后，执行控件组默认展开，不沿用上一次收起状态。
- 配置 A 运行中收起后，任务继续执行；点击恢复入口后能看到配置 A 当前运行控件，并可点击停止任务。
- 没有可见 loaded profile 时，不显示恢复入口；重新加载 profile 后按预览状态正常显示。
- P7.2.4 四个异常收尾场景在 P7.3.1 实现后继续通过。

## Assumptions

- P7.3 当前未实现，不能直接安排真机测试。
- P7.3.1 的恢复入口第一版只负责恢复执行控件组，不直接启动或停止某个 profile。
- P7.3.1 的收起状态不持久化，关闭并重开预览默认展开；后续如要记住收起状态再单独进入小阶段。
- 收起状态只影响当前预览中的悬浮执行区展示，不影响 loaded profile 数据、各 profile 执行控件位置、执行参数或单任务互斥。
- 恢复入口第一版使用固定默认位置的小型悬浮按钮，不支持拖动和位置持久化。
- 展开按钮位置持久化和横竖屏校正顺延到 P7.3.2，避免 P7.3.1 再次扩大范围。

## Risks

- 收起时隐藏当前运行控件，必须确保恢复入口始终存在，否则用户会失去停止入口。
- 收起/展开与异常收尾可能同帧发生，需要保证 `hide()`、权限撤销和无障碍断开仍能完整移除窗口并结束任务。
- 如果 P7.3.1 同时加入位置持久化和横竖屏校正，阶段范围会变大；这些能力应保留到 P7.3.2。
