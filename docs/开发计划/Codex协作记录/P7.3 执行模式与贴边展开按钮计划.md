# P7.3 执行模式与贴边展开按钮计划

## Summary

- P7.2 多配置执行控件显示、真实执行、位置持久化和异常收尾均已验证。
- P7.3 进入设计文档中的“阶段 C：执行模式”，但继续拆小步推进。
- 本轮计划建议先做 P7.3.1：执行控件组收起/展开与贴边展开按钮，不新增暂停/继续、多任务并行或 P8 高级连招。

## Scope

本轮建议包含：

- 为多配置执行区增加“展开 / 收起”状态。
- 收起时隐藏多个配置执行控件，只保留一个贴边展开按钮。
- 展开按钮支持拖动、横竖屏可见区域校正和位置持久化。
- 点击展开按钮恢复显示已加载配置执行控件。
- 正在执行任务时仍必须能通过展开按钮恢复执行控件，再点击当前运行控件停止任务。
- 保持 P7.2.4 已验证的异常收尾行为不回退。

本轮不包含：

- 暂停/继续控件。
- 多任务并行。
- 执行控件透明度、锁定位置、长按执行和二次确认。
- 控件分组、折叠面板滚动列表和复杂执行模式。
- P8 长按、滑动、延迟和高级连招。

## Plan

1. Flutter 侧新增多配置执行 UI 状态，至少包含 `isPanelCollapsed` 和 `launcherPositionX/Y`。
2. 持久化新增或复用 `multi_point.execution_ui_settings_json` 保存展开按钮位置和收起状态。
3. `show/updateMultiProfileExecutionOverlay` 向 Android 同步执行 UI 状态。
4. Android `MultiProfileExecutionOverlayManager` 在展开时显示现有多个执行控件，在收起时移除执行控件并显示贴边展开按钮。
5. 展开按钮拖动结束后回传 Flutter 持久化；横竖屏变化后沿用现有可见区域校正策略。
6. 展开按钮点击后恢复展开状态，并刷新已加载执行控件。
7. 补充模型、持久化、MethodChannel 参数和关键页面交互测试。
8. 自动化验证后真机复验收起/展开、拖动持久化、横竖屏、运行中恢复停止入口和 P7.2.4 四个异常收尾回归。

## Acceptance Criteria

- 执行控件预览开启后，用户可以收起多个执行控件，只保留一个可见的贴边展开按钮。
- 点击贴边展开按钮后，已加载的多个执行控件恢复显示，原有 profile 绑定执行能力不变。
- 展开按钮拖动后，关闭重开预览或刷新 loaded profiles 时恢复上次位置。
- 横竖屏切换后，展开按钮保持在可见区域，并保存校正后位置。
- 任务运行中如果面板处于收起状态，用户可以通过展开按钮恢复当前运行控件，并点击该控件停止任务。
- P7.2.4 四个异常收尾场景继续通过。

## Assumptions

- 展开按钮第一版只承担“恢复执行控件组”的入口，不直接开始或停止某个 profile。
- 收起状态隐藏执行控件组，但不改变 loaded profile 列表、按钮位置和单任务执行模型。
- 贴边按钮样式优先沿用现有原生悬浮组件风格，避免引入新的视觉体系。
- 先实现一个全局执行区收起状态，不做每个 profile 独立收起。

## Risks

- 收起时隐藏当前运行控件，必须确保展开按钮始终可见，否则用户会失去停止入口。
- 展开按钮位置和执行控件位置是两类状态，持久化时不能互相覆盖。
- 收起/展开与异常收尾可能同帧发生，需要保证 `hide()`、权限撤销和无障碍断开仍能完整移除窗口并结束任务。

## Verification Plan

- 自动化：`flutter analyze`、`flutter test`、`flutter build apk --debug`、`git diff --check`。
- 真机：开启预览、收起、展开、拖动展开按钮、关闭重开恢复位置、横竖屏保持可见。
- 运行中回归：配置 A 执行中收起，点击展开按钮恢复控件，再点击 A 停止。
- 异常回归：复测 P7.2.4 的关闭预览层、关闭无障碍快捷开关、撤销悬浮窗权限、隐藏当前执行配置。
