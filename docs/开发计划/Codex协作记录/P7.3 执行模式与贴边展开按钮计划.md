# P7.3 执行模式与贴边展开按钮计划

## Summary

- 本文是 P7.3 计划草案，不代表功能已经实现。
- P7.2 已完成多配置执行控件显示、真实执行、位置持久化和异常收尾专项验收。
- P7.3 需要从“计划、实现、验收”重新分层：未实现能力只进入待实现计划，不进入真机测试项。
- 当前建议先做 P7.3.1 最小实现：执行控件组收起/展开入口；实现完成后再安排真机验收。

## Scope

P7.3.1 建议包含：

- 多点页现有“执行控件”卡片内提供全局执行控件组收起/展开入口。
- Android 收起时隐藏多个 profile 执行控件，只保留一个可恢复入口。
- 点击可恢复入口后，重新显示已加载配置执行控件。
- 任务运行中收起后，仍能通过可恢复入口找回当前运行控件，并点击该控件停止任务。
- 保持 P7.2.4 已验证的异常收尾行为不回退。

P7.3.1 不包含：

- 展开按钮位置持久化。
- 横竖屏可见区域校正专项。
- 暂停/继续控件。
- 多任务并行。
- 执行控件透明度、锁定位置、长按执行和二次确认。
- 控件分组、折叠面板滚动列表和复杂执行模式。
- P8 长按、滑动、延迟和高级连招。

## Plan

1. 先实现一个全局执行控件组收起状态，不做每个 profile 独立收起。
2. Flutter 侧新增最小执行 UI 状态，仅记录当前预览生命周期内控件组是否收起；关闭并重新开启预览时默认展开。
3. `show/updateMultiProfileExecutionOverlay` 向 Android 同步收起状态。
4. Android `MultiProfileExecutionOverlayManager` 展开时显示现有多个执行控件；收起时移除执行控件并显示一个固定默认位置的小型恢复按钮，视觉复用现有悬浮组件风格。
5. 可恢复入口点击后切回展开状态，并通过回调通知 Flutter 保存状态。
6. 如果没有任何可见 loaded profile，恢复入口随执行控件预览关闭或刷新结果一并消失；重新加载 profile 后再随预览显示。
7. `hide()`、悬浮窗权限撤销、无障碍断开继续完整移除所有窗口并结束活动任务。
8. P7.3.1 自动化验证通过后，再发真机验收模板。

## Acceptance Criteria

- 开启执行控件预览后，可以从 App 页面收起执行控件组。
- 收起后多个配置执行控件不再显示，并保留一个明确可见的恢复入口。
- 点击恢复入口后，已加载配置执行控件重新显示，原有 profile 绑定执行能力不变。
- 关闭并重新开启执行控件预览后，执行控件组默认展开，不沿用上一次收起状态。
- 配置 A 运行中收起后，任务继续执行；点击恢复入口后能看到配置 A 当前运行控件，并可点击停止任务。
- 没有可见 loaded profile 时，不显示恢复入口；重新加载 profile 后按预览状态正常显示。
- P7.2.4 四个异常收尾场景在 P7.3.1 实现后继续通过。

## Assumptions

- P7.3 当前未实现，不能直接安排真机测试。
- P7.3.1 的恢复入口第一版只负责恢复执行控件组，不直接启动或停止某个 profile。
- P7.3.1 的收起状态不持久化，关闭并重开预览默认展开；后续如要记住收起状态再单独进入小阶段。
- 收起状态只影响当前预览中的悬浮执行区展示，不影响 loaded profile 数据、各 profile 执行控件位置、执行参数或单任务互斥。
- 恢复入口第一版使用固定默认位置的小型悬浮按钮，不支持拖动和位置持久化。
- 展开按钮位置持久化和横竖屏校正顺延到 P7.3.2，避免 P7.3.1 再次扩大范围。

## Implementation Changes

- Flutter 多点页“执行控件”卡片新增全局“收起执行控件组”开关。
- Flutter 侧新增当前预览生命周期内的 `isPanelCollapsed` 临时状态，关闭并重开预览时默认展开，不写入持久化。
- MethodChannel `showMultiProfileExecutionOverlay` / `updateMultiProfileExecutionOverlay` 新增 `isPanelCollapsed` 参数。
- Android `MultiProfileExecutionOverlayManager` 支持展开/收起两种展示：展开时显示现有 profile 执行控件，收起时移除执行控件并显示固定默认位置的小型恢复入口。
- 新增 `MultiProfileExecutionLauncherComponent`，第一版只负责恢复执行控件组，不支持拖动和位置持久化。
- Android 恢复入口点击后回调 `onMultiProfileExecutionPanelStateChanged`，Flutter 页面据此同步回“已展开”状态。
- Widget 测试新增覆盖：预览默认展开、收起会同步 `isPanelCollapsed=true`、原生恢复回调后页面回到展开、关闭重开预览默认展开。

## P7.3.2 Scope

本轮包含：

- Android 恢复入口支持拖动，拖动结束后回传逻辑像素坐标。
- Flutter 保存恢复入口坐标，并在下次收起时传给 Android 恢复位置。
- 横竖屏或显示边界变化后，恢复入口被校正到可见区域，并将校正后的坐标回传 Flutter。
- 保护 P7.3.1 的收起、恢复显示、默认展开和运行中恢复停止入口。
- 保护 P7.2.4 的异常收尾回归。

本轮不包含：

- 持久化收起状态。
- 单个 profile 执行控件的贴边吸附。
- 暂停/继续控件。
- 多任务并行。
- 透明度、锁定位置、长按执行和二次确认。
- 控件分组、折叠面板滚动列表和复杂执行模式。
- P8 高级连招。

## P7.3.2 Plan

1. Flutter 新增恢复入口坐标持久化，使用独立 key，不写入 `MultiPointProfile` 或 loaded profile。
2. `show/updateMultiProfileExecutionOverlay` 增加 `launcherPositionX/Y` 参数，只有存在完整坐标时传递。
3. Android 解析恢复入口坐标；收起态优先使用 Flutter 传入坐标，否则使用默认位置。
4. `MultiProfileExecutionLauncherComponent` 复用现有悬浮拖动能力，拖动结束后回传位置。
5. Android 在刷新和横竖屏边界变化时校正恢复入口坐标；如坐标变化，同步通知 Flutter 持久化。
6. Flutter 接收 `onMultiProfileExecutionLauncherPositionChanged` 后保存坐标，并更新页面内存状态。
7. 补充自动化测试覆盖参数传递、回调保存和重新开启预览后的坐标恢复。

## P7.3.2 Acceptance Criteria

- 收起执行控件组后，可以拖动恢复入口。
- 拖动恢复入口后，展开再收起或关闭重开预览后，恢复入口回到上次位置。
- 横竖屏切换或显示边界变化后，恢复入口仍保持可见，并保存校正后位置。
- 收起状态仍不持久化；关闭并重新开启执行控件预览时默认展开。
- 运行中收起后，仍可通过恢复入口展开并停止当前 profile 任务。
- P7.2.4 四个异常收尾场景不回退。

## P7.3.2 Assumptions

- 恢复入口坐标是全局执行区 UI 状态，不绑定单个 profile。
- 恢复入口坐标允许持久化；收起状态继续只属于当前预览生命周期。
- Android 和 Flutter 均使用逻辑像素坐标，Android 侧负责和 WindowManager 像素坐标互转。

## P7.3.2 Implementation Changes

- Flutter 新增 `MultiProfileExecutionLauncherPosition`，并在 `MultiPointSettingsStore` 使用独立 key 持久化恢复入口坐标。
- MethodChannel `showMultiProfileExecutionOverlay` / `updateMultiProfileExecutionOverlay` 新增 `launcherPositionX/Y` 参数。
- MethodChannel 新增 `onMultiProfileExecutionLauncherPositionChanged` 回调，用于接收拖动或边界校正后的恢复入口坐标。
- 多点页加载已保存的恢复入口坐标，并在执行控件预览刷新、收起、关闭重开时继续传给 Android。
- Android `MultiProfileExecutionLauncherComponent` 接入现有拖动能力；拖动结束后回传逻辑像素坐标。
- Android `MultiProfileExecutionOverlayManager` 在收起态优先使用 Flutter 传入坐标；横竖屏或显示边界变化时会校正到可见区域，并将校正后的坐标回传 Flutter。
- 自动化测试新增覆盖恢复入口位置持久化、MethodChannel 参数传递和关闭重开预览后的坐标恢复。
