# P5 专项验收计划

## Summary
本轮只规划 P5 剩余专项验收，不改代码、不派生工作树、不进入 P6/P7/P8。当前只读检查结果：`git status --short` 为空，工作区干净；设备已连接为 `192.168.100.101:41237`；P5 文档状态为 `[进行中]`，剩余风险集中在互斥、全禁用、权限撤销、无障碍断开和完整单点回归。

无 public API / MethodChannel / 类型变更计划；只有验收执行和记录。权限撤销类验收默认使用“手动系统设置”路径。

## 验收顺序
1. 前置确认
   - 操作：执行 `git status --short`、`adb devices`，确认 App 已安装 debug 包，首页显示无障碍“已连接”、悬浮窗“已开启”。
   - 预期：工作区无新增改动；设备为 `192.168.100.101:41237 device`；App 可正常进入单点和多点页。
   - 失败记录：命令输出、设备连接状态、首页截图、当前包安装状态。

2. `mode_conflict`：单点/多点互斥
   - 场景 A：先进入单点页，开启单点悬浮层；返回首页进入多点页，点击“开启多点悬浮层”。
   - 预期 A：多点启动被拒绝，提示“单点模式已开启，请先关闭单点模式。”；单点悬浮层仍保留；首页/页面状态不乱跳。
   - 场景 B：关闭单点；进入多点页，开启多点悬浮层；返回首页进入单点页，点击“开启单点模式”。
   - 预期 B：单点启动被拒绝，提示“多点模式已开启，请先关闭多点模式。”；多点悬浮层仍保留。
   - 失败记录：两次操作前后截图、toast/错误文案、`adb shell dumpsys window` 中 float_clicker overlay 数量、`adb logcat -d -t 300 | Select-String "mode_conflict|float_clicker|Exception"`。

3. `no_enabled_targets`：全部点位禁用后的执行拒绝
   - 操作：进入多点页，关闭所有点位开关；点击“开启多点悬浮层”；再点击“执行任务”。
   - 预期：允许保持多点编辑/悬浮模式；不显示任何多点目标点；执行被拒绝并提示“请至少启用 1 个点位后再执行。”；状态不进入 running。
   - 恢复：重新启用至少 1 个点位，确认可执行并可结束。
   - 失败记录：禁用后的页面截图、overlay 窗口数量、错误提示、恢复后是否能正常执行。

4. 悬浮窗权限撤销
   - 操作：开启多点悬浮层并保持 idle；手动进入系统“显示在其他应用上层”设置，关闭 Float Clicker 悬浮窗权限；回到 App。
   - 预期：所有多点悬浮组件消失；多点页状态回到未启动；再次开启时提示悬浮窗权限未开启；恢复权限后可重新开启，旧配置仍可用。
   - 扩展：同样对单点模式跑一次最小权限撤销验收。
   - 失败记录：撤销前后截图、`dumpsys window` 是否残留 `APPLICATION_OVERLAY`、首页权限卡片状态、logcat 中权限/窗口异常。

5. 无障碍服务运行中断开
   - 操作：开启多点悬浮层并开始执行任务；手动进入系统无障碍设置，关闭 Float Clicker 无障碍服务；回到 App。
   - 预期：任务结束；页面/首页状态回到非执行态；悬浮控件不继续显示 running；再次执行提示无障碍服务未连接；重新开启服务后可恢复执行。
   - 扩展：对单点模式执行同样断开流程。
   - 失败记录：断开前后截图、`adb shell dumpsys accessibility` 中 Bound/Enabled services、页面状态、logcat 中 `AccessibilityService` / `dispatchGesture` / `Exception` 相关日志。

6. 完整单点验收清单回归
   - 操作：按 `docs/验收清单/单点模式真机验收清单.md` 全量跑：普通、简洁、极简、外观缩放、横竖屏贴边、权限异常收尾。
   - 预期：单点三态、位置持久化、三种交互模式、全局外观、横竖屏、权限失败提示全部符合清单；多点 P5 未引入单点回退。
   - 失败记录：失败条目编号、操作步骤、截图、当前交互模式、当前任务状态、相关 logcat。

## 失败记录标准
每个失败都记录：设备与系统版本、App debug 包时间、操作路径、预期和实际、截图或 UI dump、`dumpsys window` / `dumpsys accessibility` / logcat 关键输出。若失败后状态异常，先记录再手动恢复权限和关闭悬浮层，避免覆盖现场。

## 进入代码修复的准入条件
只有满足以下任一条件才进入代码修复：
- 可稳定复现，且实际行为违反 P5 文档或验收清单。
- 原生快照、Flutter 页面状态、Overlay 窗口状态三者出现明确不同步。
- 权限撤销或无障碍断开后出现窗口残留、任务继续执行、页面长期卡在 running/paused。
- 单点模式出现 P5 前已通过能力的回退。
- logcat 出现应用崩溃、未捕获异常，或 MethodChannel 错误码/提示与既定语义不一致。

不进入代码修复的情况：单次手动误触、系统设置页路径差异、ADB/无线调试不稳定、权限恢复需要用户确认、第三方系统弹窗干扰但 App 状态可恢复。

## Assumptions
- 权限撤销和无障碍断开使用手动系统设置，不默认用 ADB 强制改权限。
- 执行验收前不改 repo 文件；验收结束后如需要更新阶段文档，先汇总结果给用户审核。
- P5 只收敛基础多点第一版，不做多配置、高级连招或新 UI 能力。
