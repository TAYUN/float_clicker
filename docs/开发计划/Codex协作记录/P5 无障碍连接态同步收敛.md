## P5 无障碍连接态同步收敛

### Summary
本轮主记录继续聚焦“无障碍连接态同步”这一条，不扩到新功能。2026-05-09 复查发现：安装当前工作区 debug 包后，真机系统侧仍显示 Float Clicker 无障碍服务 `Enabled + Bound`，但首页曾显示“服务未连接”。本轮已补强 Android 原生连接态维护，并完成首页、单点页、多点页轻量真机复验。

本次保持现有 MethodChannel 字段和错误码不变：`accessibilityGranted` 仍表示系统设置已开启，`accessibilityConnected` 仍表示严格可用的服务连接态；UI 文案继续使用“已连接 / 服务未连接”。

### Scope
- 只复验首页、单点页、多点页从系统无障碍设置返回后的状态收敛。
- 只在三组收敛复验全部通过后，才继续“运行中断开无障碍服务”专项和完整单点回归。
- 本轮不改 MethodChannel 协议、不改调度器点击语义、不进入 P6/P7/P8。

### Acceptance Criteria
- 首页在系统真实 Bound 时，允许首帧短暂未连接，但应在约 2 秒内收敛为“已连接”。
- 首页在系统真实未 Bound 时，2 秒后仍显示“服务未连接”才算正确。
- 单点页和多点页在返回前处于 `running/paused` 时，返回后不能被错误降级为 `idle`。
- 单点页和多点页在返回后，页面任务态、按钮状态和悬浮控件必须与 overlay 快照一致。
- 只有三组收敛复验全部通过，才允许继续剩余 P5 专项；否则先记录失败现场，再判断是否满足代码修复准入条件。

### Implementation Changes
- Android 侧统一无障碍状态来源：
  - 抽一个原生内部状态帮助层，统一提供 `accessibilityGranted` 和 `accessibilityConnected`。
  - `accessibilityGranted` 继续来自 `ENABLED_ACCESSIBILITY_SERVICES`，并改为用 `ComponentName.unflattenFromString()` 解析系统保存的组件名后比较，兼容完整类名和短类名。
  - `accessibilityConnected` 继续按严格可用性定义，底层由 `AccessibilityServiceStateHelper` 维护当前可用的 `FloatClickerAccessibilityService` 实例。
  - `MainActivity.getPermissionSnapshot()`、`AccessibilityServiceStateBus.addListener()`、`AccessibilityGestureExecutor.isServiceAvailable` 全部改为走这一个统一入口，避免多处判断不一致。
  - `FloatClickerAccessibilityService` 在 `onCreate()`、`onServiceConnected()`、`onUnbind()`、`onDestroy()` 中幂等注册或注销实例，避免系统已经 Bound 但 App 内静态实例未同步。

- Flutter 侧补“前台恢复后的延迟收敛”：
  - 在 `AndroidPermissionService` 增加一个仅 Flutter 内部使用的“前台刷新重试”能力：立即拉一次快照；如果结果是“`accessibilityGranted == true` 且 `accessibilityConnected == false`”，则继续按固定节奏重试，直到连接成功或超时。
  - 固定节奏直接定为：`0ms / 300ms / 1000ms / 2000ms` 共 4 次；最后一次仍未连接就保留“服务未连接”。
  - 这个重试逻辑同时拉权限快照和对应 overlay 快照，避免只更新卡片、不更新页面状态。

- 首页、单点页、多点页分别收口：
  - `HomePage`：
    - `resumed` 后不再只做一次 `_refreshPermissions()`，改为走上面的重试刷新。
    - 权限卡片完全以最新权限快照显示，不额外推断。
  - `ClickerPage`：
    - `resumed` 后改为走重试刷新。
    - 初始化和前台恢复时，不再因为一次 `permissionSnapshot.accessibilityConnected == false` 就强行把 overlay 快照的 `running/paused` 改写成 `idle`、把执行次数清零。
    - 页面任务态以原生 overlay 快照为主；只有在“权限事件明确从 connected 变成 disconnected”时，才做“任务结束并提示”的 UI 收尾。
  - `MultiPointPage`：
    - 增加 `WidgetsBindingObserver`，补齐 `resumed` 刷新。
    - 前台恢复时拉多点 overlay 快照并走同样的延迟收敛，不再只靠初次加载结果。
    - 多点页面保持“任务态以 overlay 快照为主”的语义，不用权限快照直接覆盖任务态。

- 明确不做的事：
  - 不新增第三种首页文案，例如“等待连接”。
  - 不改 MethodChannel 对外字段名、错误码、快照结构。
  - 不改单点/多点调度器的点击执行语义，只修状态同步和前台刷新。

### Test Plan
- Dart / Widget 回归：
  - `AndroidPermissionService` 新增重试逻辑测试：
    - 第 1 次返回“granted=true, connected=false”，后续返回 `connected=true` 时，应在重试窗口内收敛为已连接。
    - 4 次都 `connected=false` 时，应稳定停在“服务未连接”。
  - `HomePage` 测试：
    - 已开启但首帧未连接时，卡片先显示“服务未连接”，后续重试成功后更新为“已连接”。
  - `ClickerPage` 测试：
    - `overlaySnapshot.taskRunState=running/paused` 且首帧权限快照暂时 `connected=false` 时，页面不能被错误降成 `idle`。
    - 只有显式收到 `permissionSnapshotChanged: connected true -> false` 时，才结束任务并提示“无障碍服务已断开，点击任务已结束。”。
  - `MultiPointPage` 测试：
    - `resumed` 后会重新拉原生快照；首帧未连接但后续连接时，页面状态能收敛，不停留在错误的未连接前态。

- 真机验收：
  - 从系统无障碍设置返回首页：
    - 允许首帧短暂显示“服务未连接”，但应在 2 秒内收敛为“已连接”；若 2 秒后仍未连接，则必须与真实不可用状态一致。
  - 单点页已开启悬浮层后切到系统设置再返回：
    - 页面不能因为一次过早快照把“已开启 / running / paused”错误打回 `idle`。
  - 多点页开启悬浮层后切到系统设置再返回：
    - 页面状态、控制按钮和 overlay 快照一致。
  - 运行中关闭无障碍服务：
    - 首页/页面应回到非执行态，并保持“服务未连接”。
  - 再次重新开启无障碍服务并返回：
    - 首页和页面应在重试窗口内恢复到“已连接”，单点/多点后续可重新执行。
