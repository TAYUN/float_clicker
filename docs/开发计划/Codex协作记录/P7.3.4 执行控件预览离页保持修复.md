# P7.3.4 执行控件预览离页保持修复

## Summary

- 真实使用反馈发现：在多点模式页面加载多个配置并开启执行控件预览后，从多点页返回上一页会导致执行控件预览关闭。
- 判断该行为不符合执行控件作为长期悬浮入口的定位；只有用户显式点击“关闭执行控件预览”、权限撤销或异常收尾时才应关闭。
- 本轮做最小修复：离开多点页不主动关闭多配置执行控件，并在重新进入多点页时从 Android 原生侧恢复预览状态。

## Scope

- 包含：
  - 修复 `MultiPointPage.dispose()` 离页自动关闭执行控件的问题。
  - 增加多配置执行控件原生快照，用于恢复 `isShowing`、收起状态、恢复入口坐标和已加载控件坐标。
  - 补充 widget 回归测试，覆盖离页保持和重新进入页面状态恢复。
- 不包含：
  - 不改变“点击关闭执行控件预览会结束任务并关闭控件”的异常收尾语义。
  - 不新增 App UI。
  - 不进入暂停/继续控件、多任务并行或 P8 高级连招。

## Plan

1. 检查多点页生命周期和原生多配置执行控件状态来源。
2. 将页面销毁与显式关闭预览拆开，避免返回上一页时调用 `hideMultiProfileExecutionOverlay`。
3. 在 Android 侧暴露 `getMultiProfileExecutionOverlaySnapshot`，Flutter 侧读取后恢复页面状态。
4. 重新进入页面时同步页面外拖动产生的执行控件坐标，避免后续刷新覆盖用户移动后的位置。
5. 运行自动化验证，并给出真机复验模板。

## Acceptance Criteria

- 多点页开启执行控件预览后，返回上一页，执行控件仍保留。
- 重新进入多点页后，页面显示“预览中”，主按钮显示“关闭执行控件预览”。
- 如果执行控件组此前处于收起状态，重新进入页面后仍能显示正确收起状态。
- 用户显式点击“关闭执行控件预览”时，仍关闭执行控件并保持 P7.2.4 异常收尾语义。
- 单点/基础多点互斥不回退：多配置执行控件开启时，其他悬浮模式仍应被拒绝。

## Implementation Changes

- `MultiPointPage`：
  - 移除 `dispose()` 中的自动关闭多配置执行控件逻辑。
  - 页面初始化和前台恢复时读取多配置执行控件快照，恢复预览开关、收起状态和坐标。
- `AndroidPermissionService`：
  - 新增 `MultiProfileExecutionOverlaySnapshot`。
  - 新增 `getMultiProfileExecutionOverlaySnapshot()`。
- `MainActivity` / `MultiProfileExecutionOverlayManager`：
  - 新增原生快照返回，包含是否显示、是否收起、恢复入口位置和已加载控件位置。
- `test/widget_test.dart`：
  - 新增离开多点页不关闭执行控件的回归测试。
  - 新增重新进入多点页从原生快照恢复状态的回归测试。

## Risks

- 页面离开后如果用户继续拖动悬浮执行控件，Flutter 页面不一定在线接收位置回调；本轮通过重新进入页面时读取原生快照补写坐标来收敛。
- 该修复改变了“页面返回即关闭执行控件”的旧实现行为，需要真机确认和当前真实使用预期一致。
