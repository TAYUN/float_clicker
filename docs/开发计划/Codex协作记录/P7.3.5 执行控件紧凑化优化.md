# P7.3.5 执行控件紧凑化优化

## Summary

- 真实使用观察反馈确认：当前多配置执行控件在加载多个配置后，展开态横向矩形按钮过大，容易遮挡目标 App 内容，也会让执行区显得拥挤。
- 本轮只做一个最小体验优化：把展开态执行控件收敛为更简约的圆形样式，缩小文字并保持开始/停止入口明确。
- 本轮不进入自由横向停靠、防误触开关、暂停/继续控件或多任务并行。

## Scope

- 包含：
  - 调整 Android 多配置执行控件的展开态外观，从横向矩形改为紧凑圆形。
  - 收敛按钮文案，运行中保留明确的“停止”语义，空闲态使用更短的名称标签。
  - 保持现有拖动、位置持久化、单任务互斥、收起恢复入口和异常收尾语义不变。
- 不包含：
  - 不新增 Flutter 页面开关或新的 MethodChannel 协议。
  - 不实现自由横向停靠。
  - 不实现暂停/继续控件。
  - 不实现防误触最小开关、长按执行、二次确认、透明度或锁定位置。

## Plan

1. 复查当前多配置执行控件的尺寸、文案和默认堆叠方式，确认拥挤问题主要来自展开态按钮体积。
2. 将 Android `MultiProfileExecutionButtonComponent` 改为圆形紧凑按钮，减少横向遮挡面积。
3. 为圆形按钮增加短标签策略，避免长配置名在小按钮中挤压排版。
4. 保持 `LoadedMultiPointProfileState`、位置回调和运行状态切换协议不变，避免扩大改动面。
5. 更新阶段管理文档和本轮协作记录，记录为何优先做紧凑化而不是自由横向停靠。
6. 运行自动化验证，等待下一轮真实使用观察确认是否还需要继续拆“自由横向停靠”。

## Acceptance Criteria

- 开启执行控件预览后，展开态每个配置执行控件显示为紧凑圆形，不再是横向矩形。
- 控件空闲态文案保持居中且更短，运行态仍能明确表达“停止”。
- 多个执行控件仍支持拖动、位置持久化和运行中单任务互斥。
- 收起/展开入口、贴边恢复入口、离页保持和异常收尾行为不回退。
- 不新增新的页面配置项，也不改变当前执行链路。

## Assumptions

- 本轮的“遮挡、拥挤”痛点优先通过减小展开态控件体积缓解，而不是立即引入自由横向停靠。
- 圆形控件上的短标签只承担快速识别作用，完整配置名继续通过 `contentDescription` 保留给系统无障碍语义。
- 如果紧凑化后仍存在明显遮挡，再单独评估“自由横向停靠”是否值得作为下一小阶段。

## Implementation Changes

- `MultiProfileExecutionButtonComponent`
  - 将展开态执行控件改为圆形背景和等宽高尺寸。
  - 新增短标签生成逻辑，避免长配置名直接撑大按钮。
  - 运行态继续使用醒目的停止语义，保持用户能快速结束当前任务。
- `MultiProfileExecutionOverlayManager`
  - 同步使用新的圆形按钮尺寸做位置约束，避免边界校正仍按旧矩形宽度计算。
- `docs/开发计划/多点模式开发阶段管理.md`
  - 记录 P7.3.5 的范围、状态和下一步建议。

## Risks

- 紧凑化会降低单个按钮可承载的可见文案量，因此本轮需要依赖短标签策略；如果用户对识别度仍不满意，后续可能要再评估标签规则或自由横向停靠。
- [已收敛] 真实使用观察确认当前不再拥挤和遮挡；自由横向停靠不再作为 P7 的立即后续项。
