# 多点执行点击无效修复

## Summary

- P6 开发分支验收时发现基础多点执行有严重问题：任务状态会执行，但底层应用没有实际点击效果。
- 本问题属于基础多点 Android Overlay/调度链路，不属于 P6 profile 管理，因此从 `main` 单独切 hotfix 分支修复。
- 当前修复只处理多点目标悬浮点运行中未透传触摸的问题，不改变坐标持久化、调度顺序或 P6 数据结构。

## Scope

本轮包含：

- 给多点目标点组件补充运行中触摸透传能力。
- 在多点任务状态变化和目标点刷新后同步触摸状态。
- 补充自动化验证和真机专项验收步骤。

本轮不包含：

- 不修改 P6 多配置管理。
- 不修改多点调度顺序、暂停继续语义和点位坐标保存语义。
- 不新增 P7 多执行控件或 P8 高级动作能力。

## Implementation Changes

- `MultiPointTargetOverlayComponent` 新增 `setTouchable(isTouchable)`。
- `MultiPointOverlayManager` 在目标点刷新后同步触摸状态，避免窗口重建后丢失 `FLAG_NOT_TOUCHABLE`。
- `MultiPointOverlayManager` 在任务状态变化时同步触摸状态：
  - `running`：目标点不可触摸，点击穿透到底层应用。
  - `idle / paused`：目标点恢复可触摸，允许拖动校准。

## Acceptance Criteria

- 多点任务执行中，点击不会被多点悬浮点自身消费。
- 暂停或结束后，多点悬浮点可以继续拖动。
- 暂停中移动点位后继续执行，新位置生效。
- 单点模式原有运行中透传行为不回退。

## Risks

- 当前日志不能直接证明 dispatchGesture 失败；本轮基于单点/多点代码差异先修 Overlay 触摸透传。
- 如果真机复验仍无点击效果，下一步应排查 `centerOnScreen()` 坐标、目标应用限制和无障碍服务状态。

- 再将 `main` 合回 `codex/p6-profile-management`，让 P6 分支继承基础多点修复。
