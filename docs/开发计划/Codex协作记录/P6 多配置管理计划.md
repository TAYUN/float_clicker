# P6 多配置管理计划

## Summary

- 本轮将 P6 定位为多点配置库阶段，只做 profile 管理、持久化、页面入口和基础验收。
- P6 继续复用 P5 已验证的多点编辑、Overlay、MethodChannel 和调度链路，不改 Android 原生协议。
- P7 多配置悬浮执行区、多个执行控件、执行模式、导入导出和 P8 高级连招均不进入本轮。

## Scope

本轮包含：

- 新增 `MultiPointProfile`，将一套多点点位、点击参数和悬浮编辑设置封装为 profile。
- 新增 `multi_point.profiles_json` 和 `multi_point.active_profile_id`。
- 旧单配置首次升级时迁移为“默认配置”，并保留旧散 key 同步写入作为兼容来源。
- 多点页展示当前配置名，新增配置管理页，支持新建、复制、重命名、删除和选用配置。
- 运行中禁止配置管理；暂停和 idle 可管理配置，切换后同步当前多点 Overlay。

本轮不包含：

- 多配置悬浮执行区和多个执行控件。
- 加载 profile 到悬浮执行区。
- 执行模式、贴边展开按钮、执行控件位置持久化。
- 长按、滑动、延迟动作、导入导出和高级连招。

## Plan

- 扩展 Flutter 多点模型，新增 profile 与 profile 状态快照。
- 扩展多点持久化 store，保留 `loadConfiguration/saveConfiguration` 对外语义。
- 新增 profile 管理页面，并在多点页接入当前配置入口。
- 补充 store 单元测试和页面 widget 测试。
- 更新阶段管理文档，记录 P6 状态、验证结果和真机剩余风险。

## Acceptance Criteria

- 默认无 profile 时自动创建“默认配置”。
- 旧 `multi_point.targets_json` 等单配置数据能迁移到默认 profile。
- 多 profile 的保存、加载、切换和当前激活配置读取稳定。
- 新建、复制、重命名、删除遵守“至少保留 1 套配置”。
- 坏 `profiles_json` 不阻塞页面进入。
- 多点页能展示当前配置名，编辑点位和设置只影响当前激活 profile。
- 运行中点击配置入口会提示先暂停或结束任务。

## Assumptions

- profile id 使用本地时间戳生成，重命名和复制不复用原 id。
- 默认 profile 名称为“默认配置”，复制名称使用“原名称 副本”。
- 旧散 key 暂时继续保留，P6 不做破坏性清理。
- P6 不新增首页入口；配置入口放在多点页内。

## Implementation Changes

- 新增 `MultiPointProfile` 和 `MultiPointProfileState`。
- `MultiPointSettingsStore` 新增 profile 读写、迁移和管理方法，旧 `loadConfiguration/saveConfiguration` 仍返回当前激活配置。
- 新增 `MultiPointProfilePage`，支持配置列表、新建、复制、重命名、删除和选用。
- `MultiPointPage` 顶部展示当前配置名，进入配置管理前先保存当前配置，切换后同步多点原生设置、悬浮 UI 设置和点位。
- 补充 store 和 widget 测试覆盖 profile 迁移、管理边界和运行中禁止配置管理。

## Issues

- 2026-05-09，真机重命名配置时触发 Flutter 构建作用域断言：`_dependents.isEmpty` 和 `Tried to build dirty widget in the wrong build scope`。
- 原因判断：重命名弹窗从 `PopupMenuButton.onSelected` 里立即打开，且 `TextEditingController` 由父页面在弹窗返回后手动释放；真机输入法视口变化、菜单路由收尾和父页面 `setState` 容易撞在同一帧。
- 修复：将重命名弹窗抽成独立 StatefulWidget 自管 controller；菜单动作延后一帧执行；保存前主动收起输入法；弹窗返回后等待本帧结束再刷新 profile 列表。
- 回归：新增 widget 测试覆盖“配置操作 -> 重命名 -> 保存 -> 回到多点页展示新名称”。
