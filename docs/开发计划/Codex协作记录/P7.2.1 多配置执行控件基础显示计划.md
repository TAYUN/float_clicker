# P7.2.1 多配置执行控件基础显示计划

## Summary

- 本轮只做 P7.2 的第一小步：把 P7.1 的已加载配置同步到原生悬浮层，并显示多个配置执行控件。
- 控件本轮只承担“可见、可区分、可关闭、可横竖屏校正”的基础展示，不触发真实多配置执行。
- 继续留在 `codex/p6-profile-management` 分支，保护 P5/P6 已验证的基础多点和单点链路。

## Scope

本轮包含：

- Flutter 侧从 `loadedProfiles` 和 `profiles` 组装已加载配置快照。
- 新增最小 MethodChannel 方法，用于显示、更新、关闭多配置执行控件悬浮层。
- Android 侧新增多配置执行控件管理入口，优先复用现有窗口安全封装和外观缩放能力。
- 每个已加载配置显示一个独立控件，控件文案使用 profile 名称，默认按加载顺序纵向排列。
- 关闭多配置执行控件时完整移除窗口，不影响现有基础多点编辑悬浮层。
- 横竖屏或屏幕尺寸变化后，执行控件保持在可见区域。

本轮不包含：

- 点击控件启动、暂停、继续或结束绑定 profile 的真实任务。
- 多任务并行、执行中置灰、再次点击停止任务。
- 贴边展开按钮、执行模式隐藏点位、完整控制条切换。
- 执行控件位置持久化、透明度、锁定、防误触设置。
- 导入导出、配置分组、P8 高级连招。

## Plan

1. 梳理现有 `MultiPointOverlayManager`、`ActionButtonOverlayComponent` 和 MethodChannel 多点方法的复用边界。
2. 在 Flutter 平台服务中增加多配置执行控件的最小方法和参数结构。
3. 在多点页增加一个临时入口或沿用现有开启入口触发执行控件展示，入口文案必须能区分“编辑悬浮层”和“执行控件预览”。
4. Android 新增独立 manager 或轻量封装，负责创建、更新和移除多个 profile 执行控件。
5. 控件点击本轮只提示“执行功能将在下一阶段接入”，避免误以为已支持多配置真实执行。
6. 更新阶段文档和本协作记录，补充实现、验证、风险和下一步。

## Acceptance Criteria

- 已加载 1 套配置时，悬浮层显示 1 个配置执行控件。
- 已加载多套配置时，悬浮层显示多个控件，名称与配置管理页一致。
- 卸载或删除配置后再次展示，控件数量与 P7.1 已加载列表一致。
- 关闭控件悬浮层后无残留窗口，基础多点编辑悬浮层仍可正常开启和关闭。
- 横竖屏切换后控件仍在可见区域。
- 单点模式最小回归通过：开启单点悬浮层、关闭单点悬浮层。
- 自动化检查至少通过 `flutter analyze`、`flutter test`、`flutter build apk --debug`。

## Assumptions

- P7.1 的 `loadedProfiles` 是本轮唯一输入来源；未加载 profile 不显示控件。
- 执行控件第一版可以使用默认纵向排列，不先保存拖动位置。
- 本轮不改变 `startMultiPointClicking` 的当前 active profile 执行语义。
- 如果实现中发现基础多点编辑悬浮层和多配置执行控件同时存在会造成互斥歧义，优先让两者互斥，并在文档中记录原因。

## Risks

- 复用现有 `ActionButtonOverlayComponent` 时可能误触发基础多点任务，需要明确禁用或改为提示。
- 如果 MethodChannel 参数一次携带完整 profile 快照过大，下一阶段需要拆成轻量 loaded profile DTO。
- 执行控件位置不持久化会让体验偏临时，但这是本轮控制范围的刻意取舍。
