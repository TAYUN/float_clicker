# 多点模式开发阶段管理

## 1. 文档目的

多点模式包含基础多点、通用调度内核、后期多配置执行和高级连招等多个阶段。为了避免开发过程中范围失控，需要用本文档记录：

- 每个阶段的目标。
- 已完成任务。
- 未完成任务。
- 阶段边界和暂不做内容。
- 设计调整记录。
- 当前推荐下一步。

本文档是开发过程中的活文档。随着真机验证、代码实现和需求讨论推进，阶段计划可以调整，但每次调整都应记录原因和影响范围。

## 2. 状态标记

任务状态统一使用以下标记：

```text
[未开始] 尚未进入实现
[进行中] 正在实现或联调
[已完成] 已实现并通过基本验证
[已验证] 已完成真机或回归验收
[阻塞] 需要先解决外部问题或设计问题
[延期] 明确不进入当前阶段
[调整] 原设计发生变化，需要看调整记录
```

使用规则：

- 一个任务完成代码实现后标记为 `[已完成]`。
- 通过对应验收或回归后标记为 `[已验证]`。
- 如果需求边界变化，先标记 `[调整]`，并在“设计调整记录”中记录原因。
- 不确定是否进入当前阶段的内容先标记 `[延期]`，避免默认混入当前开发。

## 3. 迭代原则

- 开始开发前尽量把交互、状态、异常和持久化设计考虑完整，减少后续返工。
- 设计不是一次性定稿。开发中如果发现更稳、更简单或更符合用户使用习惯的方案，可以调整文档和计划。
- 所有调整都应先明确影响范围：Flutter 页面、持久化、MethodChannel、Android Overlay、调度器、验收标准。
- 除非有明确收益，不在同一阶段同时做大范围重构和新功能。
- 已稳定的单点模式必须保护，不因多点开发发生行为回退。
- 后期能力必须先进入设计文档或本计划，确认阶段边界后再实现。

## 5. P0：文档与边界确认

- 明确基础多点第一版只做多个固定点位按顺序点击。
- 明确高级连招和多配置执行属于后期能力。
- 明确运行、暂停、编辑状态下的操作规则。
- 明确风险控制方案。

任务：

- [已完成] 阅读单点模式、悬浮交互、全局外观、验收和横竖屏调试文档。
- [已完成] 补充基础多点状态操作矩阵。
- [已完成] 补充点位坐标、默认点位、最大点位数、禁用点位显示规则。
- [已完成] 补充暂停中编辑后的继续语义。
- [已完成] 补充 MethodChannel 错误码建议。
- [已完成] 补充首页全局 active mode 状态要求。
- [已完成] 新增后期多配置执行设计文档。
- [已完成] 新增阶段管理文档并维护状态标记。
- [未开始] 开始 P1 前再次检查 `git status`，确认不覆盖已有改动。

验收：

- [进行中] 文档能指导 P1 开发，不需要再临时决定核心语义。
