# 悬浮多点多配置执行设计文档

## 1. 背景与定位

基础多点模式第一版只解决一套多点任务的编辑和执行：用户维护当前点位列表，开启悬浮层后按顺序点击。

实际使用中，用户可能同时拥有多套固定操作场景：

- 场景 A 点击一组固定位置。
- 场景 B 点击另一组固定位置。
- 场景 C 使用不同的点击顺序、间隔和循环次数。

因此，多点模式后续需要从“单一当前配置”演进为“多配置管理 + 多执行入口”。

本文档描述后期能力，不进入基础多点第一版开发范围。基础多点第一版仍以《多点模式前置设计文档》为准。

## 2. 设计目标

- 支持保存多套多点点击配置。
- 支持从配置库中加载一个或多个配置到悬浮执行区。
- 每个已加载配置对应一个独立悬浮执行控件。
- 点击某个执行控件时，执行该控件绑定的多点任务。
- 执行阶段尽量简洁，可以隐藏点位和完整控制条。
- 保留明确的停止入口和展开入口，避免任务执行中用户失去控制权。
- 第一版多配置执行采用单任务执行模型，同一时间只允许一个配置任务运行。

## 3. 与基础多点模式的关系

基础多点第一版：

```text
当前多点配置
- 点位列表
- 点击参数
- 悬浮交互配置
- 执行/暂停/继续/结束
```

后期多配置执行：

```text
多点配置库
- 配置 A
- 配置 B
- 配置 C

悬浮执行区
- 配置 A 执行控件
- 配置 C 执行控件
```

关系说明：

- 多配置执行不是基础多点第一版的前置条件。
- 基础多点当前配置可以在后期升级为一个默认配置或当前编辑配置。
- 已有 `MultiPointTarget`、`MultiPointSettings`、`MultiPointOverlayUiSettings` 可以作为 `MultiPointProfile` 的内部字段复用。
- 多配置执行继续复用全局悬浮外观、悬浮窗安全封装、权限检查、横竖屏校正和手势失败收尾策略。

## 4. 冲突点与调整方案

| 潜在冲突 | 当前基础多点设计 | 多配置执行调整方案 |
| --- | --- | --- |
| 配置数量 | 只有一套当前配置 | 新增 `MultiPointProfile` 配置库，当前配置可迁移为默认 profile |
| 持久化 key | `multi_point.targets_json` 等单配置 key | 后期新增 `multi_point.profiles_json`、`multi_point.active_profile_id`、`multi_point.loaded_profile_ids_json` |
| 悬浮层形态 | 显示启用点位和一个控制体系 | 新增执行模式，只显示配置执行控件和展开按钮 |
| 执行入口 | 单个控制条或独立控件 | 多个配置执行控件，每个绑定一个 profile |
| 执行模型 | 一个多点任务运行 | 仍保持单任务执行模型，多个控件只是多个入口 |
| 点位点击间隔 | 第一版只支持全局间隔 | profile 模型可预留动作级间隔，UI 后期再开放 |
| 防误触 | 第一版只保证状态明显和停止入口 | 后期增加锁定、透明度、长按执行、二次确认等开关 |

原则：

- 不把多配置执行需求反向塞进基础多点第一版。
- 后期新增 profile 层时，应提供迁移逻辑，不丢失用户当前单配置数据。
- 执行模式只改变悬浮 UI 形态，不改变底层手势安全收尾要求。

## 5. 核心模型

### 5.1 多点配置

```text
MultiPointProfile
- id
- name
- targets
- settings
- overlayUiSettings
- orientation
- createdAt
- updatedAt
- advancedOptions
```

字段说明：

- `id`：稳定配置标识，重命名或复制不改变原配置 `id`。
- `name`：配置名称，用于 App 列表和悬浮执行控件展示。
- `targets`：点位列表，复用 `MultiPointTarget`。
- `settings`：点击参数，复用 `MultiPointSettings`。
- `overlayUiSettings`：该配置的多点悬浮编辑偏好。
- `orientation`：配置创建或校准时的屏幕方向，可取 `portrait / landscape / unknown`。
- `createdAt / updatedAt`：创建时间和更新时间。
- `advancedOptions`：后续扩展字段，避免频繁破坏 profile 顶层结构。

### 5.2 高级选项预留

```text
MultiPointProfileAdvancedOptions
- startDelayMs
- randomTapOffsetEnabled
- randomTapOffsetRadiusPx
- randomIntervalEnabled
- randomIntervalMinMs
- randomIntervalMaxMs
- perTargetIntervalEnabled
```

说明：

- 第一版多配置执行可以先持久化预留字段，但不一定开放 UI。
- `perTargetIntervalEnabled` 涉及动作级调度，后续应优先和 `AutomationAction.delayAfterMs` 对齐。
- 随机偏移和随机间隔会增加验收复杂度，应作为增强能力分阶段开放。

### 5.3 已加载配置

```text
LoadedMultiPointProfile
- profileId
- displayName
- buttonPositionX
- buttonPositionY
- order
- isVisible
```

说明：

- 已加载配置决定哪些 profile 出现在悬浮执行区。
- 执行控件位置独立保存，不污染 profile 的点位位置。
- 多个执行控件默认按 `order` 纵向排列。

### 5.4 执行模式外观设置

```text
MultiProfileExecutionUiSettings
- launcherPositionX
- launcherPositionY
- isPanelCollapsed
- opacity
- lockButtonPosition
- triggerMode
```

字段说明：

- `launcherPositionX / launcherPositionY`：贴边展开按钮位置。
- `isPanelCollapsed`：执行控件组是否收起。
- `opacity`：执行控件透明度，后期开放。
- `lockButtonPosition`：是否锁定执行控件位置，后期开放。
- `triggerMode`：执行触发方式，可取 `tap / longPress / confirm`，第一版默认 `tap`。

## 6. 配置管理能力

后期多配置模式需要支持：

- 新建配置。
- 保存当前点位为配置。
- 修改已有配置。
- 删除配置。
- 重命名配置。
- 复制配置。
- 加载一个或多个配置到悬浮执行区。
- 卸载已经加载的配置。

第一阶段多配置管理建议先做 App 内能力：

- 配置列表。
- 新建、复制、重命名、删除。
- 选择某个配置进入基础多点编辑页面。
- 保存后更新 profile。

后续增强能力：

- 配置分组。
- 搜索配置。
- 导入配置。
- 导出配置。
- 配置备份与恢复。

## 7. 编辑模式与执行模式

### 7.1 编辑模式

编辑模式用于管理配置和校准点位。

可显示：

- 悬浮点位标记。
- 点位编号。
- 多点控制条。
- 配置管理入口。
- 保存、加载、删除、重命名等操作入口。

编辑模式规则：

- 正在执行的配置不可编辑。
- 非运行配置可以编辑，但如果已加载到执行区，保存后需要同步更新执行控件名称和可执行状态。
- 如果配置没有启用点位，不允许加载到执行区。
- 如果点位明显超出当前屏幕，应提示用户重新校准。

### 7.2 执行模式

执行模式用于快速触发已加载配置。

可隐藏：

- 悬浮点位标记。
- 点位编号。
- 完整控制条。

保留：

- 一个或多个配置执行控件。
- 一个贴边展开按钮。
- 当前执行状态。
- 快速停止能力。

执行模式规则：

- 用户点击某个配置执行控件，开始执行该配置。
- 正在执行的配置控件再次点击时，执行停止操作。
- 执行期间其他配置控件置灰或提示当前已有任务运行。
- 执行完成、失败或停止后，所有控件恢复可用状态。
- 展开按钮始终可见或可通过明确手势恢复，避免用户找不到控制入口。

## 8. 多配置加载与执行控件

用户可以同时加载多个配置到悬浮执行区。

示例：

```text
操作1
操作2
操作3
```

控件行为：

- `idle`：点击开始执行绑定配置。
- `running`：点击正在运行的控件停止该配置任务。
- `running`：点击其他控件时提示当前已有任务运行，或保持置灰不可点。
- `completed`：显示短暂完成状态后回到可执行状态。
- `failed`：显示失败状态，并允许用户查看原因或重新执行。

交互建议：

- 支持拖动位置。
- 支持贴边吸附。
- 支持整体收起。
- 支持记住上次位置。
- 多个控件默认纵向排列。
- 控件数量较多时，使用折叠面板或滚动列表展示。

## 9. 执行策略

第一版多配置执行采用单任务执行模型：

```text
loaded profiles: A, B, C
running profile: B

A: disabled
B: running, tap to stop
C: disabled
```

原因：

- 多个任务并行点击屏幕容易产生点位冲突。
- 并行任务会增加暂停、停止、失败收尾和 UI 状态复杂度。
- 当前基础多点已经围绕单任务安全收尾设计，继续复用更稳。

后续如果要支持并行执行，需要重新设计：

- 多任务调度。
- 点击冲突处理。
- 多任务停止逻辑。
- 每个任务的独立状态。
- 并行任务优先级。

## 10. 隐藏与恢复机制

执行模式下可以隐藏点位和完整控制条，因此必须保留恢复控制权的入口。

需要支持：

- 一键隐藏所有点位。
- 一键显示所有点位。
- 控制条贴边收起。
- 保留小型展开按钮。
- 展开按钮可拖动。
- 记住控制条上次展开或收起状态。
- 执行过程中仍可停止任务。

硬性要求：

- 任务执行中不能出现用户找不到停止入口的状态。
- 正在执行的配置控件必须承担停止功能。
- 展开按钮不能被隐藏到屏幕外，横竖屏变化后必须校正到可见范围。

## 11. 配置修改规则

- 正在执行的配置不可编辑。
- 配置修改后，下次执行生效。
- 删除已加载配置时，对应悬浮执行控件同步移除。
- 重命名配置后，执行控件名称同步更新。
- 如果配置为空，不允许加载。
- 如果配置没有启用点位，不允许加载或执行。
- 如果点位超出屏幕，需要提示用户重新校准。
- 如果配置数据损坏，应跳过该配置并提示用户恢复、删除或重建。

## 12. 异常和权限处理

需要处理：

- 悬浮窗权限关闭。
- 无障碍权限关闭。
- 执行过程中目标应用切换。
- 屏幕横竖屏切换。
- 屏幕分辨率变化。
- 点位超出屏幕。
- 配置为空。
- 配置数据损坏。
- 执行过程中发生失败。
- 用户误触执行按钮。

策略：

- 执行前检查无障碍服务和悬浮窗权限。
- 权限不足时提示用户开启权限，不静默失败。
- 执行中权限被撤销时，立即停止任务并移除或收起悬浮执行区。
- 屏幕方向或尺寸变化后，执行控件和展开按钮都要校正到可见范围。
- 手势派发失败时，执行控件显示失败状态，并保证任务回到安全停止状态。

## 13. 防误触设计

悬浮执行控件可能长期显示在屏幕上，需要考虑误触。

第一版最低要求：

- 执行中按钮样式明显变化。
- 正在执行的控件再次点击可以快速停止。
- 其他配置控件在执行期间置灰。
- 控件位置可拖动并保存。

后续可选能力：

- 锁定悬浮控件位置。
- 调整控件透明度。
- 长按执行。
- 二次确认。
- 停止操作与开始操作使用不同样式。
- 增加“防误触模式”配置开关。

默认建议：

- 第一版多配置执行不强制二次确认。
- 后续可以新增配置开关：是否开启防误触。

## 14. 持久化建议

新增 key 建议：

```text
multi_point.profiles_json
multi_point.active_profile_id
multi_point.loaded_profile_ids_json
multi_point.loaded_profile_buttons_json
multi_point.execution_ui_settings_json
```

迁移建议：

- 如果检测到旧的 `multi_point.targets_json` 等单配置 key，但没有 `multi_point.profiles_json`，则创建一个默认 profile。
- 默认 profile 名称可为“默认配置”。
- 旧的点位、点击参数和悬浮交互设置迁移到默认 profile。
- 迁移后保留旧 key 一段时间作为回滚和兼容来源。

## 15. MethodChannel 建议

Flutter 调用 Android：

```text
showMultiProfileExecutionOverlay
hideMultiProfileExecutionOverlay
loadMultiPointProfiles
unloadMultiPointProfile
updateLoadedMultiPointProfiles
startLoadedMultiPointProfile
stopLoadedMultiPointProfile
switchMultiPointOverlayMode

```

Android 回调 Flutter：

```text
onMultiProfileExecutionStateChanged
onLoadedProfileButtonPositionChanged
onMultiProfileExecutionError
```

错误码建议：

- `profile_not_found`
- `profile_empty`
- `profile_corrupted`
- `profile_needs_recalibration`
- `mode_conflict`
- `task_already_running`
- `overlay_permission_denied`
- `overlay_window_unavailable`
- `accessibility_service_unavailable`
- `gesture_dispatch_failed`

## 16. 分阶段建议

### 16.1 阶段 A：配置库

- 新增 `MultiPointProfile`。
- 支持多个配置的保存、复制、重命名、删除。
- 当前基础多点页面可以切换编辑某个 profile。
- 不做多个悬浮执行控件。

### 16.2 阶段 B：加载配置到悬浮执行区

- 支持选择一个或多个 profile 加载。
- 显示多个配置执行控件。
- 支持卸载已加载配置。
- 执行控件位置持久化。

### 16.3 阶段 C：执行模式

- 支持隐藏点位和完整控制条。
- 显示贴边展开按钮。
- 保留停止入口。
- 支持执行中其他配置控件置灰。

### 16.4 阶段 D：增强能力

- 执行控件透明度。
- 锁定位置。
- 长按执行。
- 防误触开关。
- 配置搜索、分组、导入导出。

## 17. 当前决策

- 该需求作为基础多点第一版之后的后期能力。
- 不改变基础多点第一版“单一当前配置执行”的开发边界。
- 后期通过 `MultiPointProfile` 承载多配置。
- 多个配置可以同时加载到悬浮执行区，但同一时间只允许一个任务执行。
- 执行模式可以隐藏点位和控制条，但必须保留展开入口和停止能力。
- 每个配置执行控件同时承担开始和停止功能。
- 多配置执行第一版不支持并行点击任务。
- 配置中动作级间隔、随机偏移、随机间隔先作为模型预留或后续增强，不进入基础多点第一版。
