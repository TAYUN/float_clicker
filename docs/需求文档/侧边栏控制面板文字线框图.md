# 侧边栏控制面板文字线框图

## 1. 说明

本文档基于《侧边栏控制面板交互方案草案》和《侧边栏控制面板低保真原型说明》整理第一轮文字线框图。

本轮只用文字描述结构、信息层级和关键操作，不进入视觉稿、动效和正式实现。

## 2. 线框目标

本轮线框图只回答三个问题：

1. 侧边栏作为“全局控制壳”时，各区块该放什么信息。
2. 收起态、展开态空闲中、展开态运行中、异常提示态之间如何切换。
3. 侧边栏与现有多个 profile 执行控件如何并存，而不是互相替代。

## 3. 总体布局原则

- 侧边栏只承载全局信息和全局操作，不承载 profile 列表执行入口。
- 当前多个执行控件继续独立漂浮在内容区，保持“点击即执行”。
- 侧边栏展开后优先沿屏幕侧边贴靠，减少遮挡中心操作区域。
- 侧边栏内部只保留 2 到 3 层信息，不做滚动面板和复杂折叠区。

## 4. 状态 A：收起态入口

### 4.1 结构

```text
+----------------+
| 执行区 / 控制  |
| 运行中小标记?  |
+----------------+
```

### 4.2 信息

- 主标签：`执行区` 或 `控制`
- 轻量状态：空闲时不显示额外文本；运行中可显示一个极短状态提示，例如 `运行中`

### 4.3 操作

- 点击：展开侧边栏
- 拖动：沿用现有收起态入口拖动语义

### 4.4 目的

- 让用户知道这不是某个 profile 的按钮，而是多配置执行区的全局入口。

## 5. 状态 B：展开态空闲中

### 5.1 结构

```text
+----------------------+
| 多配置执行区         |
| 空闲中               |
| 已加载 3 个配置      |
|----------------------|
| 点击外部圆形执行控件 |
| 可启动对应配置任务   |
|----------------------|
| [收起]   [更多占位]  |
+----------------------+
```

### 5.2 分区说明

- 顶部标题区：
  - 名称：`多配置执行区`
  - 当前状态：`空闲中`
  - 已加载 profile 数量
- 中部说明区：
  - 明确提示真正执行入口仍是外部圆形执行控件
  - 不在本区展示 profile 列表，避免与方案 B 混淆
- 底部操作区：
  - `收起`
  - `更多占位`

### 5.3 目的

- 建立“侧边栏是全局控制壳，不是执行面板本体”的认知。

## 6. 状态 C：展开态运行中

### 6.1 结构

```text
+----------------------+
| 多配置执行区         |
| 运行中               |
| 当前配置：配置 A     |
|----------------------|
| 任务执行中           |
| 外部控件仍可见       |
| 但当前仅支持停止任务 |
|----------------------|
| [停止当前任务]       |
| [收起]               |
+----------------------+
```

### 6.2 分区说明

- 顶部标题区：
  - 名称：`多配置执行区`
  - 当前状态：`运行中`
  - 当前 profile 名称
- 中部状态区：
  - 说明任务正在执行
  - 提示外部控件仍存在，但当前全局重点操作是停止
- 底部操作区：
  - 主操作：`停止当前任务`
  - 次操作：`收起`

### 6.3 目的

- 强化“运行中最重要的是状态可见和停止入口可达”，而不是继续堆叠更多功能。

## 7. 状态 D：异常或权限中断后

### 7.1 结构

```text
+----------------------+
| 多配置执行区         |
| 任务已结束           |
|----------------------|
| 无障碍服务断开       |
| 或悬浮权限已撤销     |
|----------------------|
| [收起]               |
+----------------------+
```

### 7.2 分区说明

- 顶部状态改为结束态摘要，不保留“运行中”信息。
- 中部只做简短原因提示，不设计新的恢复流程。
- 底部只保留最小收起动作。

### 7.3 目的

- 与 P7 已验证的异常收尾策略保持一致，不在原型阶段新增复杂恢复链路。

## 8. 关键切换路径

### 8.1 空闲查看

```text
收起态入口
-> 点击展开
-> 展开态空闲中
-> 点击收起
-> 返回收起态入口
```

### 8.2 启动后查看状态

```text
点击外部 profile 执行控件
-> 任务启动
-> 点击收起态入口或保持展开
-> 展开态运行中
-> 查看当前配置与停止入口
```

### 8.3 运行中停止

```text
展开态运行中
-> 点击停止当前任务
-> 返回展开态空闲中
-> 可选择收起
```

### 8.4 异常结束

```text
展开态运行中
-> 无障碍断开 / 权限撤销 / 异常收尾
-> 展开态异常提示
-> 用户收起
```

## 9. 与现有执行控件的并存规则

- 外部圆形执行控件继续保留，并且仍是 profile 的真实启动入口。
- 侧边栏不接管 profile 点按执行，只提供全局摘要和停止入口。
- 如果后续线框评审认为“外部控件 + 侧边栏”仍然太分散，再回头重新评估方案 B。
- 在本轮线框中，不讨论 profile 列表如何进入侧边栏内部。

## 10. 需要确认的问题

在进入最小实现前，建议先确认以下问题：

1. 收起态入口的主标签更适合 `执行区` 还是 `控制`。
2. 展开态空闲中是否需要展示“已加载配置数量”，还是只保留空闲状态。
3. 运行中是否需要同时显示当前 profile 名称和运行状态，还是保留一个更短的摘要。
4. `更多占位` 是否在第一轮实现里完全不出现，只在文档中保留扩展位。

## 10.1 当前默认答案

为便于后续进入最小实现，当前线框图先采用以下默认答案：

1. 收起态入口主标签默认使用 `执行区`。
2. 展开态空闲中默认保留“已加载 X 个配置”。
3. 运行中默认同时显示运行状态和当前 profile 名称，保持信息可见性优先。
4. `更多占位` 不进入第一轮实现，只保留在文档层。
5. 展开侧边栏后，外部圆形执行控件默认继续保持可见，不做主动弱化。
