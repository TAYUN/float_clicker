# 全局悬浮外观配置设计文档

## 1. 背景

单点模式的悬浮点、控制条、收起图标和独立执行控件已经进入可用状态，但不同设备、不同应用场景对悬浮控件大小的偏好不同：

- 小屏或遮挡敏感场景，希望控件更小。
- 横屏游戏或远距离操作场景，希望控件更容易点中。
- 后续多点模式也会复用悬浮点、控制条和独立执行控件，不应再单独维护一套尺寸配置。

因此需要增加一个全局悬浮外观配置，让用户可以调整悬浮控件整体大小，并保证单点模式和后续多点模式共享同一套配置。

## 2. 设计结论

建议先做这个功能，不必等多点模式完善后再做。

原因：

- 当前单点模式已经有稳定的悬浮组件拆分，正适合把硬编码尺寸收敛成共享尺寸模型。
- 如果等多点模式完成后再做，单点和多点大概率会各自复制一套尺寸常量，后续统一成本更高。
- 这个功能天然是跨模式基础设施，不依赖多点点击逻辑本身。

但第一版范围要收窄：

- 第一版只做一个全局整体缩放比例。
- 不做每个组件单独大小配置。
- 不做每个模式单独大小配置。
- 不改变点击任务配置、交互模式和各组件位置的保存语义。

## 3. 配置定义

### 3.1 全局外观配置

新增全局配置模型：

```text
GlobalOverlayAppearanceSettings
- overlayControlScale
```

字段说明：

- `overlayControlScale`：悬浮控件整体缩放比例。
- 默认值：`1.0`。
- 建议范围：`0.8` 到 `1.3`。
- 建议步进：`0.05`。

说明：

- 该比例作用于悬浮点、完整控制条、收起图标、独立执行控件，以及后续多点模式中的点位标记和复用控制组件。
- 缩放只影响控件视觉尺寸、触摸区域、边界校正尺寸和内部图标尺寸。
- 缩放不改变已保存的位置坐标含义；位置仍然使用逻辑像素保存。

### 3.2 持久化 key

全局配置使用 `global.*` key，避免和单点、多点模式配置混在一起：

```text
global.overlay_control_scale
```

后续如果增加更多全局悬浮外观配置，可以继续使用：

```text
global.overlay_opacity
global.overlay_theme
```

## 4. UI 入口

第一版推荐在单点设置页中增加“全局悬浮外观”区域，并明确标注“对单点模式和后续多点模式生效”。

原因：

- 当前应用还没有独立的全局设置页。
- 用户调整控件大小的场景通常发生在单点模式调试悬浮组件时。
- 这样可以先满足需求，同时不提前设计完整应用设置中心。

后续当多点模式或更多全局配置出现时，可以把该区域迁移到首页的“全局设置”页面。迁移时保留同一套 `global.*` 持久化 key，不需要迁移用户数据。

建议 UI：

- 使用滑块调节整体大小。
- 显示当前百分比，例如 `100%`。
- 提供一键恢复默认值。
- 文案使用“悬浮控件大小”，避免暴露实现细节。

建议档位：

```text
80% / 90% / 100% / 110% / 120% / 130%
```

## 5. 架构设计

### 5.1 Flutter 侧

新增共享模型和存储：

```text
GlobalOverlayAppearanceSettings
GlobalOverlayAppearanceStore
```

职责：

- `GlobalOverlayAppearanceSettings`：描述跨模式悬浮外观配置。
- `GlobalOverlayAppearanceStore`：读写 `global.*` key。
- 单点设置页读取并保存该配置。
- 单点模式开启或配置保存时，将该配置传给 Android 原生侧。

注意：

- 不要把 `overlayControlScale` 放进 `OverlayUiSettings`。
- `OverlayUiSettings` 继续只负责交互模式、收起状态和组件位置。
- 单点、多点各自的位置配置仍独立保存。
- 全局外观配置由所有模式共享。

### 5.2 MethodChannel 协议

建议扩展现有悬浮配置参数：

```text
overlayControlScale: Double
```

涉及调用：

- `showSinglePointOverlay`
- `updateSinglePointOverlayUiSettings`

也可以新增更明确的方法：

```text
updateGlobalOverlayAppearanceSettings
```

推荐第一版采用“新增独立方法 + show 时附带当前值”的方式：

- `showSinglePointOverlay` 附带当前 `overlayControlScale`，保证首次创建时尺寸正确。
- `updateGlobalOverlayAppearanceSettings` 用于悬浮组件已显示时即时刷新尺寸。

后续多点模式复用同一个全局更新方法。

### 5.3 Android 原生侧

新增原生模型：

```text
OverlayAppearanceSettings
- controlScale: Float
```

新增尺寸计算层：

```text
OverlayComponentMetrics
- targetSizeDp
- targetStrokeDp
- targetInnerDotDp
- toolbarWidthDp
- toolbarButtonWidthDp
- toolbarButtonHeightDp
- toolbarPaddingHorizontalDp
- toolbarPaddingVerticalDp
- collapsedToolbarSizeDp
- actionButtonSizeDp
- actionIconSizeDp
```

职责：

- 所有组件尺寸从 `OverlayComponentMetrics` 获取，不再在组件里散落硬编码 dp。
- `OverlayComponentMetrics` 根据基础尺寸和 `controlScale` 计算最终尺寸。
- 边界校正也必须使用同一套 metrics，避免视觉尺寸和可拖动边界不一致。

示例：

```text
base targetSizeDp = 38
base toolbarWidthDp = 42
base actionButtonSizeDp = 42
final targetSizeDp = round(base targetSizeDp * controlScale)
```

尺寸下限：

- 为避免控件过小导致误触，缩放后的独立执行控件和收起图标不应小于 `34dp`。
- 悬浮点不应小于 `30dp`。
- 控制条按钮高度不应小于 `28dp`。

尺寸上限：

- 为避免遮挡过大，缩放后的独立执行控件不应大于 `58dp`。
- 控制条宽度不应大于 `58dp`。

### 5.4 多点模式复用边界

多点模式后续应复用：

- `GlobalOverlayAppearanceSettings`
- `GlobalOverlayAppearanceStore`
- `OverlayAppearanceSettings`
- `OverlayComponentMetrics`
- 完整控制条、收起图标、独立执行控件的尺寸规则

多点模式只应独立维护：

- 多点点位列表和位置。
- 多点任务配置。
- 多点模式的执行顺序和任务状态。

## 6. 和现有配置的关系

当前已有配置分为：

- 点击任务配置：描述点击行为。
- 悬浮交互配置：描述模式、收起状态和组件位置。
- 全局悬浮外观配置：描述跨模式控件大小。

三者不要合并。

```text
ClickerSettings
- intervalMs
- repeatCount
- infiniteLoop
- tapDurationMs

OverlayUiSettings
- interactionMode
- targetPosition
- toolbarPosition
- collapsedToolbarPosition
- actionButtonPosition
- isToolbarCollapsed

GlobalOverlayAppearanceSettings
- overlayControlScale
```

## 7. 更新规则

保存全局悬浮外观配置后：

- 如果单点模式未开启，只保存配置，下次开启时生效。
- 如果单点模式已开启，立即通知 Android 刷新当前悬浮组件尺寸。
- 如果任务正在执行或暂停，刷新尺寸不应结束任务。
- 刷新尺寸后，原生侧需要重新校正位置，确保组件仍在屏幕可见范围内。
- 组件位置坐标仍按左上角逻辑像素保存；尺寸变化后可以允许组件视觉中心略有变化。

后续多点模式开启时同理：

- 全局尺寸更新应同步刷新多点模式当前悬浮组件。
- 单点和多点不应同时运行；如果未来支持并存，需要由统一 OverlayManager 分发全局外观更新。

## 8. 验收标准

- 设置页可以调整悬浮控件整体大小，并保存。
- 重启 App 后，全局悬浮控件大小保持用户设置。
- 单点模式开启时，调整大小后当前悬浮点、控制条、收起图标、独立执行控件立即刷新。
- 缩放后拖动、点击、长按仍正常。
- 缩放后横竖屏切换和贴边逻辑仍正常。
- 缩放后任务执行、暂停、继续、结束状态不丢失。
- 后续多点模式接入时，不需要新增另一套全局大小配置。

## 9. 推荐实施阶段

### 第一阶段：全局配置模型和文档落地

- 新增 Flutter 全局外观配置模型。
- 新增全局配置持久化。
- 单点设置页增加全局大小入口。
- 暂不改 Android 尺寸，先保证配置能保存和读回。

### 第二阶段：Android 尺寸 metrics 化

- 新增 `OverlayAppearanceSettings`。
- 新增 `OverlayComponentMetrics`。
- 把单点模式现有硬编码尺寸迁移到 metrics。
- 支持 `showSinglePointOverlay` 使用当前全局缩放。

### 第三阶段：即时刷新

- 新增 `updateGlobalOverlayAppearanceSettings` MethodChannel 方法。
- 单点模式已开启时，保存全局外观配置后即时刷新悬浮组件。
- 刷新后回传校正后的位置给 Flutter 持久化。

### 第四阶段：多点模式复用

- 多点模式接入同一套全局配置和 Android metrics。
- 多点只维护自己的点位和任务配置，不新增全局大小配置。
