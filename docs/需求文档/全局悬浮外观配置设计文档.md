# 全局悬浮外观配置设计文档

## 1. 背景

单点模式的悬浮点、控制条、收起图标和独立执行控件已经进入可用状态，但不同设备和使用场景对控件大小的偏好不同：

- 小屏或遮挡敏感场景，希望控件更小。
- 横屏游戏或远距离操作场景，希望控件更容易点中。
- 后续多点模式会复用悬浮点、控制条和独立执行控件，不应再维护另一套尺寸配置。

因此悬浮外观配置必须是全局配置，由单点模式和后续多点模式共享。

## 2. 当前设计结论

当前版本采用“全局入口 + 分组件缩放”的方案：

- 首页提供“全局设置”入口。
- 全局设置页提供“悬浮外观”配置区。
- 支持分别调节悬浮点位、控制条、独立执行控件大小。
- 收起图标属于控制条的收起形态，跟随控制条大小。
- 配置保存后，如果单点模式已开启，会立即刷新当前悬浮组件。
- 刷新尺寸不应结束任务，也不应清空执行进度。

这套配置现在先服务单点模式，后续多点模式必须复用同一套模型、持久化 key 和 Android metrics。

## 3. 配置定义

### 3.1 Flutter 模型

```text
GlobalOverlayAppearanceSettings
- targetPointScale
- toolbarScale
- actionButtonScale
```

字段说明：

- `targetPointScale`：悬浮点位大小比例。
- `toolbarScale`：完整控制条和收起图标大小比例。
- `actionButtonScale`：独立执行控件大小比例。
- 默认值：`1.0`。
- 可调范围：`0.8` 到 `1.3`。
- 步进：`0.05`。

兼容字段：

- `overlayControlScale` 当前仍保留为兼容旧 Android 协议的派生值。
- 派生规则为三个分项比例的平均值。
- 新 Android 端应优先读取三个分项比例，不应再只依赖 `overlayControlScale`。

### 3.2 持久化 key

新版本使用三个分组件 key：

```text
global.overlay.target_point_scale
global.overlay.toolbar_scale
global.overlay.action_button_scale
```

旧版本 key：

```text
global.overlay_control_scale
```

迁移规则：

- 如果新 key 不存在，但旧 `global.overlay_control_scale` 存在，则用旧值初始化三个新字段。
- 保存后写入三个新 key。
- 旧 key 暂时保留为只读迁移来源，不再作为主配置写入。

## 4. UI 入口

首页增加“全局设置”入口。

全局设置页结构：

```text
全局设置
- 悬浮外观
  - 悬浮点位大小
  - 控制条大小
  - 独立控件大小
  - 恢复默认
  - 保存
```

单点设置页只负责：

- 点击参数。
- 单点悬浮交互模式。

单点设置页不再直接承载全局外观配置，避免用户误解为该配置只对单点模式生效。

## 5. MethodChannel 协议

`showSinglePointOverlay` 和 `updateGlobalOverlayAppearanceSettings` 都应携带全局外观配置。

新协议字段：

```text
targetPointScale: Double
toolbarScale: Double
actionButtonScale: Double
```

兼容字段：

```text
overlayControlScale: Double
```

兼容规则：

- Flutter 仍发送 `overlayControlScale`，用于兼容旧 Android 端。
- Android 新端优先读取三个分项字段。
- 如果某个分项字段缺失，Android 使用 `overlayControlScale` 作为 fallback。

## 6. Android 原生侧

Android 原生模型：

```text
OverlayAppearanceSettings
- targetPointScale: Float
- toolbarScale: Float
- actionButtonScale: Float
```

Android 尺寸计算层：

```text
OverlayComponentMetrics
```

职责：

- 悬浮点尺寸、描边、内部圆点使用 `targetPointScale`。
- 完整控制条、控制条按钮、收起图标使用 `toolbarScale`。
- 独立执行控件和内部播放/暂停图形使用 `actionButtonScale`。
- 边界校正必须使用同一套 metrics，避免视觉尺寸和可拖动边界不一致。

位置规则：

- 已保存位置仍然使用左上角逻辑像素。
- 缩放不改变坐标语义。
- 缩放后原生侧需要重新校正位置，确保组件仍在可见范围内。

## 7. 和现有配置的关系

当前配置分为三类：

```text
ClickerSettings
- intervalMs
- repeatCount
- infiniteLoop
- tapDurationMs

OverlayUiSettings
- interactionMode
- targetPosition
- toolbarPosition
- collapsedToolbarPosition
- actionButtonPosition
- isToolbarCollapsed

GlobalOverlayAppearanceSettings
- targetPointScale
- toolbarScale
- actionButtonScale
```

边界：

- 点击任务配置描述点击行为。
- 悬浮交互配置描述模式、收起状态和位置。
- 全局悬浮外观配置描述跨模式控件大小。
- 不要把全局外观配置放进 `OverlayUiSettings`。

## 8. 更新规则

保存全局悬浮外观配置后：

- 如果单点模式未开启，只保存配置，下次开启时生效。
- 如果单点模式已开启，立即通知 Android 刷新当前悬浮组件尺寸。
- 如果任务正在执行或暂停，刷新尺寸不应结束任务。
- 刷新尺寸后，原生侧需要重新校正位置，确保组件仍在屏幕可见范围内。
- 后续多点模式开启时同理复用。

## 9. 验收标准

- 首页存在“全局设置”入口。
- 全局设置页可以分别调整悬浮点位、控制条、独立控件大小。
- 旧 `global.overlay_control_scale` 可以迁移为三个新比例。
- 重启 App 后，三个比例保持用户设置。
- 单点模式开启时，调整大小后当前悬浮点、控制条、收起图标、独立执行控件立即刷新。
- 三个滑块分别影响对应组件，不互相覆盖。
- 缩放后拖动、点击、长按仍正常。
- 缩放后横竖屏切换和贴边逻辑仍正常。
- 缩放后任务执行、暂停、继续、结束状态不丢失。
- 后续多点模式接入时，不新增另一套全局大小配置。

## 10. 已完成阶段

- Flutter 新增全局设置入口。
- Flutter 拆分 `GlobalOverlayAppearanceSettings` 为三个比例。
- Flutter 持久化三个 `global.overlay.*` key。
- Flutter 支持旧 `global.overlay_control_scale` 迁移。
- MethodChannel 新增三比例字段，并保留旧 `overlayControlScale`。
- Android `OverlayAppearanceSettings` 支持三个比例。
- Android `OverlayComponentMetrics` 按组件分别缩放。
- 单点模式运行中调整大小不会打断任务。
- 单点模式已补充 `WindowManager` 安全封装，外观刷新或组件重建时窗口异常不会直接导致 App 崩溃。

## 11. 后续阶段

- 多点模式接入同一套全局外观配置。
- 根据真机反馈决定是否把“收起图标大小”从控制条大小中拆出独立配置。
- 根据用户反馈决定是否增加透明度、主题色等全局外观配置。
