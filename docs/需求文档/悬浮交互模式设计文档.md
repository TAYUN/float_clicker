# 悬浮交互模式设计文档

## 1. 背景

Float Clicker 的悬浮组件需要适配不同使用场景：

- 有些页面需要完整控制条，方便用户理解和操作。
- 有些页面空间紧张，需要减少悬浮组件遮挡。
- 后续多点模式也会需要相同的交互形态切换能力。

因此，悬浮交互不应只绑定在单点模式的一套固定 UI 上，而应抽象成可复用的交互配置。

## 2. 设计目标

- 支持普通、简洁、极简三种悬浮交互模式。
- 将点击任务配置和悬浮交互配置拆开保存。
- 将任务状态从二态升级为三态，支持暂停和结束的差异。
- 独立执行控件、控制条、点位组件可以分别显示、拖动和保存位置。
- 为后续多点模式复用同一套交互模型预留边界。
- 支持跨模式复用全局悬浮外观配置，例如悬浮控件整体大小。

## 3. 概念定义

### 3.1 任务状态

点击任务状态使用三态模型：

| 状态 | 含义 | 下一步单击行为 |
| --- | --- | --- |
| `idle` | 未执行，或任务已结束 | 开始执行 |
| `running` | 正在执行点击任务 | 暂停任务 |
| `paused` | 已暂停，保留当前执行进度 | 继续执行 |

状态语义：

- 暂停：停止继续调度下一次点击，但保留当前任务进度。
- 继续：从暂停进度继续执行。
- 结束：停止调度并清空本轮进度，下次从头开始执行。

### 3.2 交互模式

悬浮交互模式使用枚举表示：

| 模式 | 含义 |
| --- | --- |
| `normal` | 普通模式，显示控制条和点位 |
| `compact` | 简洁模式，控制条可收起，收起后使用独立执行控件 |
| `minimal` | 极简模式，不显示控制条，只显示点位和独立执行控件 |

## 4. 三种模式规则

### 4.1 普通模式

显示组件：

- 悬浮点位组件。
- 悬浮控制条。

控制条包含：

- 拖动按钮。
- 执行/暂停/继续按钮。
- 结束任务按钮。
- 关闭悬浮模式按钮。

交互规则：

- 拖动按钮用于移动控制条。
- 点击执行按钮后任务进入 `running`。
- 点击暂停按钮后任务进入 `paused`。
- 点击继续按钮后任务回到 `running`。
- 点击结束任务按钮时，任务进入 `idle`，悬浮组件保留。
- 点击关闭悬浮模式按钮时，任务进入 `idle`，并移除当前模式的全部悬浮组件。

### 4.2 简洁模式

显示组件：

- 悬浮点位组件。
- 悬浮控制条，支持展开和收起。
- 控制条收起后显示独立执行控件。

展开状态：

- 行为接近普通模式。
- 点击拖动按钮图标时，控制条收起成一个小图标。
- 拖动按钮仍支持拖动控制条。
- 拖动距离超过阈值时只移动控制条，不触发收起。

收起状态：

- 控制条显示为一个可拖动的小图标。
- 单击小图标展开完整控制条。
- 拖动收起图标时只移动图标，不触发展开。
- 独立执行控件显示在屏幕上。
- 独立执行控件根据任务状态切换显示：
  - `idle`：显示执行。
  - `running`：显示暂停。
  - `paused`：显示继续。
- 独立执行控件的单击、长按和拖动规则与第 5 节一致。

### 4.3 极简模式

显示组件：

- 悬浮点位组件。
- 独立执行控件。

不显示组件：

- 悬浮控制条。

交互规则：

- 单击独立执行控件：
  - `idle` -> `running`
  - `running` -> `paused`
  - `paused` -> `running`
- 长按独立执行控件：
  - `running` 或 `paused` -> `idle`
  - 清空当前任务进度。
- 独立执行控件可拖动并保存位置。
- App 页面内仍保留暂停、继续和结束任务的入口。

## 5. 独立执行控件手势规则

独立执行控件需要区分单击、长按和拖动：

| 手势 | 行为 |
| --- | --- |
| 单击 | 执行、暂停、继续 |
| 长按 | 结束当前任务 |
| 拖动 | 移动控件位置 |

误触控制：

- 长按建议阈值为 600-800 ms。
- 拖动距离超过阈值后，本次手势只移动控件，不触发单击或长按。
- 长按触发时建议提供轻微反馈，例如颜色变化、缩放或震动。
- `idle` 状态下长按不执行危险操作，可以忽略或保持原状态。

## 6. 配置拆分

### 6.1 点击任务配置

点击任务配置只描述点击执行规则：

- 点击间隔。
- 点击次数。
- 是否无限循环。
- 点击持续时间。

示例：

```text
ClickerSettings
- intervalMs
- repeatCount
- infiniteLoop
- tapDurationMs
```

### 6.2 悬浮交互配置

悬浮交互配置只描述组件形态、显示策略和位置：

```text
OverlayUiSettings
- interactionMode
- targetPosition
- toolbarPosition
- collapsedToolbarPosition
- actionButtonPosition
- isToolbarCollapsed
```

单点模式持久化 key 建议：

```text
single_point.overlay_interaction_mode
single_point.target_position_x
single_point.target_position_y
single_point.toolbar_position_x
single_point.toolbar_position_y
single_point.collapsed_toolbar_position_x
single_point.collapsed_toolbar_position_y
single_point.action_button_position_x
single_point.action_button_position_y
single_point.is_toolbar_collapsed
```

后续多点模式可以使用相同结构，但切换到 `multi_point.*` key，避免不同模式互相污染位置和交互偏好。

### 6.3 全局悬浮外观配置

全局悬浮外观配置描述所有模式共享的悬浮控件视觉偏好，不属于单点或多点的模式内配置。

第一版只定义整体缩放：

```text
GlobalOverlayAppearanceSettings
- overlayControlScale
```

持久化 key：

```text
global.overlay_control_scale
```

约束：

- 该配置对单点模式和后续多点模式同时生效。
- 不应放入 `OverlayUiSettings`。
- 不应使用 `single_point.*` 或 `multi_point.*` key 保存。
- 缩放影响悬浮点、控制条、收起图标、独立执行控件及后续多点模式复用的悬浮组件。
- 缩放不改变组件位置坐标的保存语义。

## 7. 原生 Overlay 组件拆分

Android 原生侧建议拆成独立组件管理，而不是把所有逻辑写进一个工具条：

```text
OverlayManager
- TargetOverlayComponent
- ToolbarOverlayComponent
- CollapsedToolbarComponent
- ActionButtonOverlayComponent
- OverlayInteractionState
```

职责建议：

- `OverlayManager`：维护模式、任务状态、组件显隐和状态通知。
- `TargetOverlayComponent`：负责点位显示、拖动和坐标读取。
- `ToolbarOverlayComponent`：负责完整控制条显示、拖动和按钮事件。
- `CollapsedToolbarComponent`：负责收起图标显示、拖动和展开事件。
- `ActionButtonOverlayComponent`：负责独立执行控件显示、拖动、单击和长按。
- `OverlayInteractionState`：记录当前模式、是否收起、组件位置和任务状态。

## 8. 状态同步

Flutter 和 Android 原生侧都需要理解同一套状态：

```text
TaskRunState
- idle
- running
- paused
```

原生侧是任务执行和悬浮组件的事实来源。Flutter 页面负责：

- 展示当前配置。
- 发起模式切换。
- 发起执行、暂停、继续、结束。
- 接收原生侧状态回调并刷新页面。

原生侧负责：

- 创建、更新和移除悬浮组件。
- 按交互模式控制组件显隐。
- 保存或回传组件位置。
- 调度点击任务。
- 处理暂停、继续和结束。

## 9. 模式切换规则

用户修改交互模式后，如果悬浮组件已显示，应立即同步到原生侧并刷新当前悬浮组件：

- `normal` -> `compact`：保留点位，控制条支持收起。
- `compact` -> `normal`：显示完整控制条，隐藏独立执行控件。
- `compact` -> `minimal`：隐藏控制条和收起图标，保留点位和独立执行控件。
- `minimal` -> `compact`：恢复控制条，按配置决定展开或收起。
- `minimal` -> `normal`：显示完整控制条，隐藏独立执行控件。

切换模式不应默认结束任务。正在执行或暂停时切换模式，只改变控制组件形态，任务状态保持不变。

## 10. 验收要点

- 普通模式显示点位和完整控制条。
- 简洁模式展开时显示完整控制条，点击拖动图标可收起。
- 简洁模式收起后，单击收起图标可展开控制条。
- 极简模式不显示控制条，只显示点位和独立执行控件。
- 独立执行控件可拖动并保存位置。
- 独立执行控件单击可执行、暂停、继续。
- 独立执行控件长按可结束任务，且不应和拖动、单击冲突。
- 暂停后继续执行时保留当前进度。
- 结束后再次执行时从头开始。
- App 页面内可以控制执行、暂停、继续和结束。
- 切换交互模式后，已显示的悬浮组件立即刷新。
- 修改全局悬浮控件大小后，已显示的悬浮组件立即刷新，任务状态保持不变。
