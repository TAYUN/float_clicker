# 多点模式前置设计文档

## 1. 背景与目标

Float Clicker 当前单点模式已经完成三态任务调度、普通/简洁/极简悬浮交互、全局悬浮外观配置和主要异常收尾。下一阶段准备进入多点模式设计。

多点模式不能简单理解为“复制多个单点”。它需要解决多个点位的管理、执行顺序、任务进度、悬浮组件复用、后续长按/滑动/连招扩展等问题。因此本设计先明确两条产品线边界：

- 基础多点模式：面向普通用户，解决多个固定位置按顺序自动点击。
- 高级连招模式：面向复杂自动化，支持点击、长按、滑动、延迟等动作编排。

本阶段目标是先设计基础多点，并在底层模型上为高级连招预留扩展，不在第一版多点中直接堆复杂动作 UI。

多点模式后续还会包含“多配置管理 + 多执行入口”等能力。这类能力不进入基础多点第一版，单独在《悬浮多点多配置执行设计文档》中设计，并由《多点模式开发阶段管理》跟踪阶段状态。

## 1.1 文档维护原则

多点模式比单点模式复杂，设计不应一边写代码一边临时决定核心语义。进入每个开发阶段前，应尽量提前确认：

- 用户交互边界。
- 状态模型。
- 持久化结构。
- MethodChannel 协议。
- Android Overlay 复用关系。
- 调度和异常收尾策略。
- 验收标准。

同时，本文档不是一次性定稿。随着开发、真机验证和需求讨论推进，如果发现更稳、更简单或更符合用户习惯的方案，可以调整设计，但需要遵守：

- 调整前先说明原因和影响范围。
- 同步更新相关需求文档、阶段管理文档和验收标准。
- 不把后期能力无意识塞进当前阶段。
- 不因多点模式调整破坏已稳定的单点模式。

## 2. 设计结论

建议采用“两层能力，一套执行内核”的方案：

```text
基础多点模式
- 用户管理多个点击点
- 按点位顺序执行 tap
- 使用简单设置：间隔、次数、无限循环、点击持续时间

高级连招模式
- 用户编辑动作列表
- 动作可以是 tap / longPress / swipe / delay
- 支持更复杂的编排、命名、导入导出等后续能力

共享执行内核
- 使用 AutomationAction 描述可执行动作
- 单点、多点、连招最终都转换为动作序列执行
```

这样第一版不会把多点页面做得过重，但以后增加长按、滑动和复杂连招时，不需要推翻 Android 调度器。

## 3. 功能边界

### 3.1 基础多点模式包含

- 开启和关闭多点模式。
- 新增、删除、拖动多个点击点。
- 点击点显示序号，例如 `1 / 2 / 3`。
- 点击点位置持久化。
- 支持启用或禁用单个点位。
- 按点位顺序依次点击。
- 支持点击间隔、循环次数、无限循环、点击持续时间。
- 支持任务三态：`idle / running / paused`。
- 支持执行、暂停、继续、结束任务。
- 支持普通、简洁、极简三种悬浮交互模式。
- 复用全局悬浮外观配置。
- 复用悬浮窗异常收尾、横竖屏贴边、权限检查等单点稳定性策略。

### 3.2 基础多点模式暂不包含

- 单个点位配置不同的点击间隔。
- 单个点位配置不同的点击次数。
- 长按动作。
- 滑动动作。
- 复杂延迟动作。
- 条件判断、图像识别、找色。
- 录制用户轨迹。
- 脚本导入导出。
- 多套方案管理。
- 多配置同时加载到悬浮执行区。
- 多个配置执行控件。
- 动作分组、嵌套循环、随机化执行。

这些能力应进入高级连招模式或后期多配置执行阶段，而不是挤进基础多点第一版。

### 3.3 高级连招模式包含方向

高级连招模式用于表达复杂自动化动作，建议后续独立入口或从多点模式升级进入。

动作类型建议：

```text
AutomationAction
- tap(targetId, durationMs)
- longPress(targetId, durationMs)
- swipe(fromTargetId, toTargetId, durationMs)
- delay(durationMs)
```

后续可扩展：

- 动作命名。
- 动作复制、删除、拖拽排序。
- 每个动作独立配置执行后延迟。
- 动作序列重复。
- 方案保存和切换。
- 导入导出。

高级连招不建议作为多点第一版主流程，因为它会显著增加 UI、状态和验收复杂度。

### 3.4 后期多配置执行方向

多配置执行用于保存多套多点任务，并把一个或多个配置加载到悬浮执行区。

方向：

```text
MultiPointProfile
- 配置名称
- 点位列表
- 点击参数
- 悬浮编辑偏好
- 屏幕方向
- 创建和更新时间

悬浮执行区
- 配置 A 执行控件
- 配置 B 执行控件
- 配置 C 执行控件
```

设计边界：

- 不进入基础多点第一版。
- 后期通过 `MultiPointProfile` 承载多配置。
- 多个配置可以同时加载到悬浮执行区，但同一时间只允许一个任务执行。
- 执行模式可以隐藏点位和控制条，但必须保留展开入口和停止能力。
- 详细设计以《悬浮多点多配置执行设计文档》为准。

## 4. 用户场景

### 4.1 基础多点场景

用户需要反复点击多个固定位置，例如：

- 先点按钮 A，再点按钮 B，再点确认。
- 在游戏或工具中依次点击多个固定控件。
- 重复完成一组固定点击流程。

用户进入多点模式后，添加多个点位，拖到目标位置，点击执行。任务按 `1 -> 2 -> 3` 顺序循环执行。

### 4.2 高级连招场景

用户需要执行更复杂的操作，例如：

- 长按某个位置。
- 从一个位置滑动到另一个位置。
- 点击后等待一段时间，再继续下一步。
- 多个动作组成一套可重复执行的操作链。

这类场景需要动作列表和更强的编辑能力，应由高级连招模式承载。

## 5. 核心模型设计

### 5.1 多点点位

```text
MultiPointTarget
- id
- order
- label
- x
- y
- enabled
```

字段说明：

- `id`：稳定标识，不能因排序变化而改变。
- `order`：执行顺序。
- `label`：展示名称，默认可使用序号；显示序号应根据当前排序重新计算，不依赖 `id`。
- `x / y`：点位悬浮组件左上角坐标。真正执行点击时，Android 根据当前 `OverlayComponentMetrics` 把左上角换算为点位中心坐标。
- `enabled`：是否参与执行。

约束：

- 至少需要 1 个启用点位才能开始任务。
- 点位对象第一版不允许删除到 0 个；如果只剩 1 个点位，删除按钮应禁用或提示用户至少保留 1 个点位。
- 允许用户把所有点位都禁用，但执行和继续任务时必须拒绝，并提示至少启用 1 个点位。
- 删除点位后需要重新整理显示序号，但不要求复用已删除的 `id`。
- 点位 `id` 是稳定身份；排序、删除后重新编号只影响显示序号和执行顺序，不改变剩余点位的 `id`。
- App 页面列表按完整点位顺序显示；多点悬浮层按启用点位的执行顺序显示连续序号。
- 拖动点位过程中，如果任务正在运行，后续执行应使用最新坐标。
- 第一版建议最多支持 12 个点位，避免悬浮层拥挤和调度状态过重。
- 首次进入多点模式时默认创建 2 个启用点位，默认放在屏幕右侧中部附近并上下错开，降低用户理解成本；用户可以删除到只保留 1 个点位。
- 新增点位默认追加到列表末尾，位置基于最后一个点位向下错开；如果超出屏幕可见范围，由 Android `OverlayWindowHelper` 校正到可见范围内。

### 5.2 多点任务配置

基础多点第一版建议复用单点点击配置语义：

```text
MultiPointSettings
- intervalMs
- repeatCount
- infiniteLoop
- tapDurationMs
```

执行含义：

- `intervalMs`：两个动作之间的间隔。
- `repeatCount`：整组点位序列重复次数。
- `infiniteLoop`：无限循环整组点位序列。
- `tapDurationMs`：每个点位单次点击持续时间。

说明：

- 第一版不支持每个点位独立 interval/duration，避免基础模式 UI 过重。
- 后续如果用户强烈需要单点独立参数，应优先放进高级连招模式。

### 5.3 多点悬浮交互配置

多点模式复用已有 `OverlayInteractionMode`：

```text
OverlayInteractionMode
- normal
- compact
- minimal
```

多点模式需要独立保存组件位置和收起状态：

```text
MultiPointOverlayUiSettings
- interactionMode
- toolbarPosition
- collapsedToolbarPosition
- actionButtonPosition
- isToolbarCollapsed
```

点位位置由 `MultiPointTarget` 保存，不放在 `OverlayUiSettings` 内。

### 5.4 全局悬浮外观配置

多点模式必须复用当前全局配置：

```text
GlobalOverlayAppearanceSettings
- targetPointScale
- toolbarScale
- actionButtonScale
```

含义：

- `targetPointScale`：影响所有多点点位。
- `toolbarScale`：影响完整控制条和收起图标。
- `actionButtonScale`：影响独立执行控件。

多点模式不新增另一套大小配置。

### 5.5 通用动作模型

为了后续高级连招，建议 Android 调度内核先围绕动作抽象设计：

```text
AutomationAction
- id
- type
- targetId
- fromTargetId
- toTargetId
- durationMs
- delayAfterMs
```

基础多点可以转换为动作序列：

```text
targets: [1, 2, 3]

actions:
- tap(targetId: 1, durationMs: tapDurationMs)
- tap(targetId: 2, durationMs: tapDurationMs)
- tap(targetId: 3, durationMs: tapDurationMs)
```

高级连招后续再直接暴露 `AutomationAction` 编辑 UI。

## 6. 执行语义

### 6.1 基础多点执行顺序

有限次数示例：

```text
enabled targets: 1, 2, 3
repeatCount: 2

执行顺序:
1 -> 2 -> 3 -> 1 -> 2 -> 3 -> idle
```

无限循环示例：

```text
enabled targets: 1, 2, 3
infiniteLoop: true

执行顺序:
1 -> 2 -> 3 -> 1 -> 2 -> 3 -> ...直到用户暂停、结束或关闭模式
```

### 6.2 暂停与继续

暂停规则：

- 如果当前没有正在派发的手势，立即进入 `paused`。
- 如果当前手势正在执行，不强行中断手势，等当前手势回调后停止调度下一步。
- 暂停需要保留当前轮次和当前动作索引。

继续规则：

- 从暂停时保留的进度继续。
- 不重新执行已经完成的动作。
- 如果暂停时点位位置发生变化，继续后使用最新点位坐标。
- 如果暂停期间只修改点位位置或悬浮外观，继续时沿用原来的当前轮次和动作索引。
- 如果暂停期间新增、删除、启用、禁用或重排点位，继续时保留已完成轮次，但从当前轮的第一个启用点位重新开始。
- 如果暂停期间修改为有限循环，且新的 `repeatCount` 小于或等于已完成轮次，点击继续时应直接结束任务并回到 `idle`，提示任务已达到新的循环次数。
- 继续前必须重新校验权限、悬浮层状态和启用点位数量；如果没有启用点位，则拒绝继续并提示用户。

### 6.3 结束任务

结束规则：

- 任务状态进入 `idle`。
- 清空当前轮次和动作索引。
- 悬浮组件保留，除非用户关闭多点模式。
- 下次执行从第一个启用点位开始。

### 6.4 配置变化

任务运行中允许的变化：

- 拖动点位：允许，后续动作使用最新坐标。
- 拖动控制条、收起图标、独立执行控件：允许。
- 切换悬浮交互模式：允许，不结束任务。
- 调整全局悬浮外观：允许，不结束任务。

任务运行中需要谨慎处理的变化：

- 新增点位。
- 删除点位。
- 禁用当前或后续点位。
- 修改点击间隔、次数、无限循环。

第一版建议：

- 运行中允许修改位置和悬浮外观。
- 运行中不允许新增、删除、重排、启禁点位；需要先暂停或结束。
- 暂停中允许完整编辑点位列表；如果点位结构变化，继续时从当前轮第一个启用点位重新开始。

### 6.5 任务状态下的操作规则

多点模式使用 `idle / running / paused` 三态，但页面交互需要进一步明确哪些操作可以执行。

#### 6.5.1 编辑态：`idle`

`idle` 是主要编辑状态，多点模式可以未开启，也可以只开启悬浮层但未执行任务。

| 操作 | 是否允许 | 说明 |
| --- | --- | --- |
| 新增点位 | 允许 | 新点位追加到最后，自动生成序号 |
| 删除点位 | 允许 | 删除后重排显示序号，至少保留 1 个启用点位才能执行 |
| 启用或禁用点位 | 允许 | 禁用点位不参与执行 |
| 调整顺序 | 允许 | App 页面列表排序后，悬浮点序号同步刷新 |
| 拖动悬浮点位 | 允许 | 如果悬浮层已开启，拖动后保存位置 |
| 修改点击参数 | 允许 | 间隔、循环次数、无限循环、点击持续时间保存后生效 |
| 修改交互模式 | 允许 | 悬浮层已开启时立即刷新 |
| 修改全局外观 | 允许 | 悬浮层已开启时立即刷新 |
| 开始任务 | 允许 | 开始前校验权限、悬浮层和启用点位 |

#### 6.5.2 运行态：`running`

`running` 需要保护执行序列。第一版原则是：位置可以变，结构不能变。

| 操作 | 是否允许 | 说明 |
| --- | --- | --- |
| 新增点位 | 禁止 | 提示用户先暂停或结束任务 |
| 删除点位 | 禁止 | 避免删除当前或后续目标导致索引失效 |
| 启用或禁用点位 | 禁止 | 避免执行列表突然变化 |
| 调整顺序 | 禁止 | 避免当前轮次和动作索引失效 |
| 拖动悬浮点位 | 允许 | 后续点击使用最新位置 |
| 修改点击参数 | 禁止 | 第一版避免运行中变更次数和间隔导致进度语义复杂 |
| 修改交互模式 | 允许 | 只刷新控制组件形态，不影响任务 |
| 修改全局外观 | 允许 | 只刷新尺寸和可见边界，不清空进度 |
| 暂停任务 | 允许 | 保留当前轮次和动作索引 |
| 结束任务 | 允许 | 清空进度并回到 `idle` |
| 关闭多点模式 | 允许 | 先结束任务，再移除悬浮组件 |

#### 6.5.3 暂停态：`paused`

`paused` 是半编辑态，允许用户修正点位和配置，但继续前需要重新校验。

| 操作 | 是否允许 | 说明 |
| --- | --- | --- |
| 新增点位 | 允许 | 标记点位结构已变化 |
| 删除点位 | 允许 | 标记点位结构已变化 |
| 启用或禁用点位 | 允许 | 标记点位结构已变化 |
| 调整顺序 | 允许 | 标记点位结构已变化 |
| 拖动悬浮点位 | 允许 | 继续后使用最新位置 |
| 修改点击参数 | 允许 | 继续后按新配置执行；如果新的有限循环次数已达到，则继续时直接结束 |
| 修改交互模式 | 允许 | 立即刷新悬浮层 |
| 修改全局外观 | 允许 | 立即刷新，不清空暂停进度 |
| 继续任务 | 允许 | 如果点位结构变化，从当前轮第一个启用点位重新开始 |
| 结束任务 | 允许 | 清空进度并回到 `idle` |

补充规则：

- 点位结构变化指新增、删除、启用、禁用或重排点位。
- 暂停中只拖动点位位置，不视为点位结构变化。
- 暂停中点位结构变化后，已完成轮次保留，当前轮未完成部分按新的启用点位顺序重新开始。

### 6.6 进度字段语义

为避免 Flutter 页面和 Android 调度器对进度含义理解不一致，多点快照中的进度字段采用以下语义：

- `completedRounds`：已经完整执行完的点位序列轮次数，从 `0` 开始计数。
- `currentRound`：当前正在执行或暂停所在轮次，给 UI 展示时使用 `1` 起始；`idle` 且无进度时可以为 `0`。
- `executedActionCountInCurrentRound`：当前轮已经完成的动作数量。
- `currentTargetId`：当前正在派发手势的点位，或下一步即将执行的点位；`idle` 时可以为空。

补充规则：

- 有限循环任务结束条件以 `completedRounds >= repeatCount` 为准。
- 暂停中点位结构变化后，`completedRounds` 保留，`executedActionCountInCurrentRound` 重置为 `0`，继续时从当前轮第一个启用点位开始。
- 如果点位结构未变化，只修改位置或悬浮外观，则继续时保留 `executedActionCountInCurrentRound`。

## 7. 悬浮组件设计

### 7.1 多点点位组件

基础多点需要新的多点点位组件：

```text
MultiPointTargetOverlayComponent
```

职责：

- 展示一个可拖动点位。
- 显示序号或标签。
- 回传拖动后位置。
- 支持选中态或编辑态。

视觉建议：

- 继承单点悬浮点的蓝色圆环语言。
- 用序号区分多个点。
- 保持尺寸受 `targetPointScale` 控制。
- 避免每个点都加入复杂按钮，防止屏幕拥挤。
- 第一版悬浮层只显示启用点位；禁用点位保留在 App 页面列表中，但不创建悬浮点，避免遮挡。
- 悬浮点序号按启用点位的执行顺序连续显示，例如完整列表中禁用第 2 个点后，悬浮层显示 `1 / 2` 而不是 `1 / 3`。

### 7.2 多点 Overlay Manager

建议新增独立管理类：

```text
MultiPointOverlayManager
- MultiPointTargetOverlayComponent list
- ToolbarOverlayComponent
- CollapsedToolbarComponent
- ActionButtonOverlayComponent
- OverlayInteractionState
```

复用：

- `ToolbarOverlayComponent`
- `CollapsedToolbarComponent`
- `ActionButtonOverlayComponent`
- `OverlayWindowHelper`
- `OverlayAppearanceSettings`
- `OverlayComponentMetrics`

新增：

- 多点点位列表管理。
- 多点点位排序和显示。
- 多点模式状态快照。

### 7.3 控制条行为

基础多点的控制条不需要新增复杂按钮。第一版可复用单点控制语义：

- 执行。
- 暂停。
- 继续。
- 结束任务。
- 关闭多点模式。

点位新增、删除、排序建议先放在 Flutter 多点页面中完成，不在悬浮控制条中展开，以免悬浮 UI 过重。

### 7.4 悬浮层交互边界

第一版多点悬浮层定位为执行面板，不承担完整编辑器职责。

悬浮层负责：

- 展示多个可拖动编号点位。
- 只展示启用点位，并按启用点位执行顺序显示连续序号。
- 展示当前交互模式对应的控制组件。
- 执行、暂停、继续、结束任务。
- 关闭多点模式。
- 回传点位和控制组件拖动后的位置。

悬浮层不负责：

- 新增点位。
- 删除点位。
- 调整点位顺序。
- 修改点位启用状态。
- 编辑长按、滑动、延迟等复杂动作。

这些编辑操作统一放在 Flutter 多点页面，避免悬浮窗遮挡过多内容，也避免每个点位组件承载过多按钮。

## 8. Android 手势能力评估

Android `AccessibilityService.dispatchGesture()` 可以支持：

- 点击：短时长 `StrokeDescription`。
- 长按：较长时长 `StrokeDescription`。
- 滑动：使用 `Path` 从起点移动到终点。

因此技术上可以支持长按和滑动。但设计上不建议基础多点第一版直接暴露这些复杂动作。

原因：

- 长按和滑动需要每个动作独立配置 duration。
- 滑动需要两个坐标点或一条路径，编辑成本高于普通点位。
- 复杂动作需要动作列表、排序、参数编辑和更细的验收。
- 如果塞进基础多点，会让普通用户的多点点击流程变复杂。

建议：

- Android 调度器底层为 `AutomationAction` 预留 `longPress / swipe / delay`。
- Flutter 第一版多点页面只生成 `tap` 动作。
- 后续高级连招页面再开放完整动作编辑。

## 9. 持久化设计

### 9.1 基础多点配置 key

```text
multi_point.interval_ms
multi_point.repeat_count
multi_point.infinite_loop
multi_point.tap_duration_ms
```

### 9.2 多点点位 key

建议将点位列表保存为结构化 JSON 字符串：

```text
multi_point.targets_json
```

示例：

```json
[
  {"id":"p1","order":1,"label":"1","x":120.0,"y":300.0,"enabled":true},
  {"id":"p2","order":2,"label":"2","x":260.0,"y":480.0,"enabled":true}
]
```

说明：

- 点位是列表数据，使用单个 JSON key 比 `target_1_x` 这类散 key 更容易迁移。
- 后续增加字段时可做版本兼容。
- `targets_json` 保存完整点位列表，包括禁用点位；悬浮层是否显示由 `enabled` 决定。
- `order` 保存完整列表顺序，执行前再过滤启用点位并生成连续显示序号。

### 9.3 多点悬浮交互 key

## 10. MethodChannel 协议建议

### 10.1 多点模式方法

Flutter 调用 Android：

```text
showMultiPointOverlay
hideMultiPointOverlay
updateMultiPointSettings
updateMultiPointTargets
updateMultiPointOverlayUiSettings
updateGlobalOverlayAppearanceSettings
startMultiPointClicking
pauseMultiPointClicking
resumeMultiPointClicking
endMultiPointClicking
getMultiPointOverlaySnapshot
```

Android 回调 Flutter：

```text
onMultiPointOverlayStateChanged
onMultiPointTargetPositionChanged
onMultiPointTaskStateChanged
onOverlayError
```

### 10.2 快照字段

```text
MultiPointOverlaySnapshot
- modeEnabled
- taskRunState
- completedRounds
- currentRound
- executedActionCountInCurrentRound
- currentTargetId
- targets
- overlayUiSettings
- errorCode
```

说明：

- `completedRounds` 表示已经完整完成的轮次数。
- `currentRound` 表示当前执行到第几轮，给 UI 展示时使用 `1` 起始。
- `executedActionCountInCurrentRound` 表示当前轮已完成动作数。
- `currentTargetId` 用于页面展示当前正在执行或即将执行的点位。
- `targets` 需要包含 Android 校正后的最新位置，且应包含完整点位列表，包括禁用点位。

### 10.3 错误码建议

多点模式第一版建议使用稳定错误码，方便 Flutter 页面统一展示中文提示。

| 错误码 | 含义 | 建议提示 |
| --- | --- | --- |
| `mode_conflict` | 单点或其他模式已开启 | 请先关闭当前运行的模式，再开启多点模式 |
| `no_enabled_targets` | 没有启用点位 | 请至少启用 1 个点位 |
| `overlay_permission_denied` | 悬浮窗权限未开启 | 请先开启悬浮窗口权限 |
| `overlay_window_unavailable` | 悬浮窗创建或更新失败 | 悬浮窗创建失败，请确认权限后重试 |
| `accessibility_service_unavailable` | 无障碍服务未连接 | 请先开启并连接无障碍服务 |
| `invalid_task_state` | 当前任务状态不支持该操作 | 当前状态无法执行此操作 |
| `gesture_dispatch_failed` | 手势派发失败或被系统取消 | 点击手势被系统拒绝，任务已停止 |

## 11. Flutter 页面建议

### 11.1 首页

首页多点入口从“开发中”调整为可进入，但可根据实现阶段标记：

- 设计中。
- 基础多点可用。
- 高级连招后续支持。

多点接入后，首页“当前运行状态”需要从单点专用状态升级为全局运行状态：

- 未启动。
- 单点模式已开启。
- 单点任务执行中。
- 单点任务已暂停。
- 多点模式已开启。
- 多点任务执行中。
- 多点任务已暂停。

首页状态应以原生侧当前 active mode 快照为准，避免单点和多点页面各自维护局部状态导致显示不一致。

### 11.2 多点模式页面

第一版建议页面结构：

```text
多点模式
- 状态面板
- 点位列表
- 新增点位
- 删除点位
- 调整顺序
- 设置入口
- 开启/关闭多点模式
- 执行/暂停/继续/结束任务
```

设计约束：

- 点位编辑在 App 页面完成。
- 悬浮层只负责展示点位和执行控制。
- 运行中禁用新增、删除、重排，避免执行序列突变。
- `idle` 且多点悬浮层已开启时，新增、删除、启禁、排序后应立即刷新悬浮点。
- `paused` 中编辑点位结构后也应立即刷新悬浮点，同时标记点位结构已变化，继续时按第 6.2 节规则处理。

### 11.3 多点设置页面

设置区：

- 点击间隔。
- 循环次数。
- 无限循环。
- 点击持续时间。
- 悬浮交互模式。

不放全局悬浮外观配置。全局外观继续由首页“全局设置”维护。

### 11.4 高级连招入口

高级连招建议后续独立页面：

```text
高级连招
- 动作列表
- 添加点击
- 添加长按
- 添加滑动
- 添加延迟
- 动作参数编辑
- 方案保存
```

入口可以放在多点模式页面中，但第一版先展示“后续支持”即可。

## 12. Android 架构建议

### 12.1 调度器拆分

建议不要让 `SinglePointClickScheduler` 继续膨胀成所有模式调度器。

后续可以演进为：

```text
AutomationTaskScheduler
- start(actions, repeatPolicy)
- pause()
- resume()
- end()
- currentState()
```

单点模式：

```text
actions = [tap(singleTarget)]
```

基础多点模式：

```text
actions = targets.map { tap(it) }
```

高级连招模式：

```text
actions = userEditedActions
```

### 12.2 坐标提供者

动作执行前需要读取最新坐标，建议使用坐标提供者：

```text
TargetPositionProvider
- positionOf(targetId)
```

价值：

- 点位运行中拖动后，下一次动作使用最新坐标。
- `AutomationAction` 不直接保存过期坐标。
- 单点、多点、连招都可以共用。

### 12.3 手势执行器

建议抽出低层执行器：

```text
AccessibilityGestureExecutor
- tap(x, y, durationMs)
- longPress(x, y, durationMs)
- swipe(fromX, fromY, toX, toY, durationMs)
```

职责：

- 统一处理 `dispatchGesture()` 返回 `false`。
- 统一处理手势完成、取消、服务断开。
- 向调度器返回成功或失败。

这样调度器只关心动作序列，不直接拼 `GestureDescription`。

### 12.4 架构落地顺序

通用动作内核是目标架构，但落地时应小步迁移，避免影响已经稳定的单点模式。

推荐顺序：

1. 先实现 Flutter 多点模型、持久化和页面，明确点位列表、配置和状态语义。
2. 新增 Android 多点 Overlay，不改动单点 Overlay 主链路，优先复用控制条、收起图标、独立执行控件、外观 metrics 和 `OverlayWindowHelper`。
3. 抽出 `AccessibilityGestureExecutor`，统一处理 tap 和 `dispatchGesture()` 失败、取消、服务断开等低层收尾。
4. 新增或抽出 `AutomationTaskScheduler`，让基础多点先接入动作序列。
5. 单点模式在多点稳定后再评估是否迁移到通用调度器，迁移时必须保持现有单点验收不回退。

约束：

- 不让 `SinglePointClickScheduler` 继续膨胀为多模式调度器。
- 不在第一版多点页面暴露 `longPress / swipe / delay`。
- 不为了抽象一次性重写单点 Overlay 和调度链路。

## 13. 异常与边界

- 无障碍未授权或服务未连接时，禁止开始任务。
- 悬浮窗权限缺失时，禁止开启多点悬浮层。
- 启用点位数量为 0 时，禁止开始任务。
- 点位被拖到屏幕外时，需要通过 `OverlayWindowHelper` 校正到可见范围。
- 屏幕旋转后，所有点位和控制组件都需要重新校正。
- `dispatchGesture()` 返回 `false` 时，任务必须结束并回到 `idle`。
- 手势取消时，任务必须结束或进入安全停止状态，不能卡在 `running`。
- 删除点位时，如果任务正在运行，应先暂停或结束。
- 无限循环时，必须保证 App 页面和悬浮层都有明确结束入口。
- 多点和单点不应同时运行。开启一个模式前需要关闭或拒绝另一个模式。
- 第一版采用保守互斥策略：如果单点模式已开启，多点开启应返回 `mode_conflict`，Flutter 提示用户先关闭单点；不自动关闭单点或静默切换。

### 13.1 风险控制方案

| 风险点 | 控制方案 |
| --- | --- |
| 多点复用单点模型导致命名混乱 | 第一阶段可先复用 `TaskRunState` 和 `OverlayInteractionMode`；如果后续出现明显跨模块依赖，再小步抽到 `core`，避免当前阶段大重构 |
| 点位坐标语义不统一 | 持久化统一保存悬浮组件左上角；Android 执行点击时根据当前组件尺寸换算中心点 |
| 单点和多点同时运行 | 原生侧维护模式互斥。第一版建议开启一个模式时，如果另一个模式已开启，则提示用户先关闭或确认切换，不静默切换 |
| 运行中修改点位结构导致执行序列失效 | `running` 禁止新增、删除、启禁、排序；只允许拖动位置、切换交互模式和调整全局外观 |
| 暂停中编辑后继续语义复杂 | `paused` 允许完整编辑；如果点位结构变化，继续时保留已完成轮次，从当前轮第一个启用点位重新开始 |
| 调度器过早重构影响单点稳定性 | 先新增多点能力，再抽手势执行器和通用调度器；单点迁移放到多点稳定后评估 |
| 悬浮层编辑能力过重 | 第一版悬浮层只展示点位和执行控制，新增、删除、排序、启禁统一在 Flutter 页面完成 |
| 多点数量过多导致遮挡和性能问题 | 第一版限制最多 12 个点位，后续根据真机反馈调整 |

## 14. 验收标准

基础多点第一版验收：

- 用户可以进入多点模式页面。
- 首次进入多点模式时默认存在 2 个启用点位。
- 第一版最多允许 12 个点位，超过上限时新增按钮应禁用或提示。
- 用户可以新增多个点位。
- 点位显示序号。
- 点位可以拖动并持久化位置。
- 用户可以删除点位并保持序号正确。
- 用户不能删除到 0 个点位对象。
- 用户可以禁用全部点位，但执行和继续任务会被拒绝并提示至少启用 1 个点位。
- 禁用点位不显示在悬浮层，重新启用后恢复显示。
- 用户可以调整点位执行顺序。
- 权限完整时可以开启多点悬浮层。
- 悬浮层显示所有启用点位和当前交互模式的控制组件。
- 悬浮层点位序号按启用点位执行顺序连续显示。
- 普通、简洁、极简三种交互模式行为与单点一致。
- 控制条或独立执行控件可以执行、暂停、继续、结束任务。
- 任务按启用点位顺序点击。
- 暂停后继续时不重头执行。
- 暂停中点位结构变化后，继续时保留已完成轮次，并从当前轮第一个启用点位重新开始。
- 暂停中把有限循环次数改为小于或等于已完成轮次后，点击继续会直接结束任务。
- 结束后再次执行从第一个启用点位开始。
- 运行中新增、删除、启禁、排序和修改点击参数入口不可用，并提示先暂停或结束任务。
- 运行中拖动点位后，后续点击使用新位置。
- `idle` 或 `paused` 中编辑点位结构时，如果悬浮层已开启，悬浮点立即刷新。
- 单点模式已开启时，开启多点模式会被拒绝并提示先关闭单点模式。
- 首页可以正确展示多点模式已开启、执行中和已暂停状态。
- 修改全局悬浮外观后，多点悬浮组件立即刷新且任务不中断。
- 横竖屏切换后所有点位和控制组件保持可见。
- 权限撤销、服务断开、手势派发失败时任务安全收尾。

高级连招后续验收：

- 可创建 tap / longPress / swipe / delay 动作。
- 可调整动作顺序。
- 可编辑每个动作参数。
- 可执行、暂停、继续、结束动作序列。
- 滑动动作使用两个点位或起止坐标。
- 长按和滑动失败时能安全收尾。

## 16. 当前决策

- 下一阶段建议先做基础多点点击，不直接做复杂连招。
- 长按、滑动、延迟应在底层动作模型中预留，但不进入基础多点第一版 UI。
- 高级连招应作为独立模式或高级入口，避免干扰普通多点用户。
- 多配置管理和多个悬浮执行入口属于后期能力，不进入基础多点第一版。
- 多点模式必须复用单点已稳定的悬浮交互、任务三态、全局外观和异常收尾策略。
- 单点与多点同一时间只允许一个模式处于开启状态。
- 多点点位持久化坐标统一使用悬浮组件左上角，执行点击时由 Android 换算中心点。
- 第一版默认创建 2 个点位，最多支持 12 个点位。
- 第一版不允许删除到 0 个点位对象；允许禁用全部点位，但执行和继续会被拒绝。
- 第一版悬浮层只显示启用点位，禁用点位只在 App 页面列表中展示。
- 点位显示序号按当前排序重新计算，`id` 始终保持稳定。
- 新增点位默认基于最后一个点位向下错开，并由 Android 校正到可见范围。
- `running` 状态只允许位置、悬浮交互和全局外观变化，不允许点位结构变化。
- `paused` 状态允许完整编辑；点位结构变化后继续时，从当前轮第一个启用点位重新开始。
- 暂停中把有限循环次数改到已完成轮次以内时，继续会直接结束任务。
- 悬浮层只作为执行面板，点位新增、删除、排序和启禁统一放在 Flutter 页面。
- 多点开启遇到单点已开启时返回 `mode_conflict`，由 Flutter 提示用户先关闭单点，不自动切换。
- 首页运行状态需要升级为全局 active mode 状态，覆盖单点和多点。
- 架构上按小步演进实现，除非特别说明，后续开发默认按本文档补充后的方案执行。
- 每个开发阶段的状态、完成情况和设计调整记录由《多点模式开发阶段管理》维护。
- 文档允许随开发迭代更新，但核心语义调整必须同步更新需求、计划和验收标准。
