# 侧边栏控制面板低保真原型说明

## 1. 原型定位

本文档用于承接《侧边栏控制面板交互方案草案》的下一步，不直接进入正式功能实现，只描述第一轮低保真原型需要验证的核心问题、页面状态和交互路径。

本轮原型只服务于一个目标：验证“侧边栏只做全局控制壳”是否值得继续推进。

## 2. 原型目标

本轮低保真原型只验证以下四个问题：

1. 用户是否更容易理解“收起态入口”和“展开态全局控制区”的关系。
2. 当前运行状态和停止入口是否比现有方案更容易被发现。
3. 在保留多个 profile 执行控件的前提下，侧边栏是否能降低入口分散感。
4. 新增侧边栏后，是否会明显增加遮挡、误触或状态切换负担。

## 3. 原型边界

本轮原型包含：

- 收起态入口形态定义。
- 展开态侧边栏的信息层级与操作分区。
- 侧边栏与现有多个执行控件同时存在时的关系。
- 运行中与空闲态的差异化展示。

本轮原型不包含：

- `P8` 长按、滑动、延迟和高级连招。
- 多任务并行。
- 暂停/继续控件。
- 防误触设置、透明度、锁定位置等扩展配置。
- 完整视觉稿、颜色细节、动画与像素级尺寸。
- Flutter、MethodChannel 或 Android Overlay 正式代码。

## 4. 推荐原型方向

第一轮原型采用“方案 A：侧边栏只做全局控制壳”，即：

- 保留现有多个 profile 执行控件作为真实执行入口。
- 新增一个侧边栏控制面板，统一承载全局状态摘要、收起/展开、停止当前任务和更多操作入口。
- 侧边栏不承载 profile 列表点击执行，不替代当前多执行控件。

这样做的原因是：

- 能先验证“统一壳层”本身是否有价值。
- 不会过早重构已经验证过的多执行控件链路。
- 如果验证失败，回退成本更低。

## 5. 核心界面状态

### 5.1 状态 A：收起态

目标：

- 让用户一眼识别这是“执行区的全局入口”，而不是某个 profile 的执行按钮。

建议展示：

- 一个可拖动的轻量入口。
- 入口上显示简短全局语义，例如“执行区”或“控制”。
- 若当前有任务运行，可增加非常轻的运行态提示，但不在收起态堆叠过多信息。

用户动作：

1. 点击入口，展开侧边栏。
2. 长按、双击等复杂交互不进入本轮原型。

### 5.2 状态 B：展开态空闲中

目标：

- 帮用户快速理解“这里是全局控制壳，不是替代各 profile 按钮的执行面板”。

建议分区：

1. 顶部状态区：
   - 显示当前状态为“空闲”。
   - 显示已加载 profile 数量。
2. 中部说明区：
   - 明确提示“点击外部执行控件可启动对应配置”。
3. 底部操作区：
   - 收起入口。
   - 预留“更多操作”占位，但不在本轮定义具体内容。

### 5.3 状态 C：展开态运行中

目标：

- 在不改变现有真实执行入口的前提下，让“当前正在运行什么”和“如何停止”更醒目。

建议分区：

1. 顶部状态区：
   - 显示“运行中”。
   - 显示当前运行的 profile 名称。
2. 中部说明区：
   - 保留“外部执行控件仍可见，但当前只有停止当前任务可用”的语义提示。
3. 底部操作区：
   - 一个明确的“停止当前任务”入口。
   - 一个“收起”入口。

### 5.4 状态 D：异常或权限中断后

目标：

- 保持与 P7 已验证的异常收尾语义一致，不新增复杂恢复流。

建议展示：

- 侧边栏只显示任务已结束或服务已断开的摘要提示。
- 不在原型阶段设计复杂引导弹层。

## 6. 与现有执行控件的关系

本轮原型必须明确以下关系：

- 多个圆形执行控件继续保留，仍负责“点击即执行”。
- 侧边栏负责“看全局状态、收起展开、停止当前任务、承接未来扩展入口”。
- 侧边栏不是 profile 编辑入口，不进入配置管理页逻辑。
- 运行中的 profile 仍由现有执行控件链路决定，侧边栏只做摘要和全局控制补充。

## 7. 原型交互路径

建议只画以下 3 条最小路径：

1. 空闲态：
   - 收起态入口
   - 点击展开
   - 查看空闲摘要
   - 收起返回

2. 启动后查看状态：
   - 点击某个 profile 执行控件启动任务
   - 点击侧边栏入口展开
   - 查看当前运行 profile 与停止入口

3. 运行中停止：
   - 侧边栏展开态
   - 点击“停止当前任务”
   - 返回空闲态摘要

## 8. 原型验收标准

完成第一轮低保真原型后，应至少能回答：

- 用户能否区分“全局侧边栏入口”和“profile 执行按钮”。
- 侧边栏是否真的提升了运行状态可见性。
- 停止入口是否更容易被发现。
- 侧边栏是否引入明显的新遮挡或额外步骤。
- 若答案偏正向，是否值得进入最小实现阶段。

## 9. 原型交付形式建议

本轮交付形式建议从轻量到重依次选择：

1. 先用文档中的状态说明和简图描述达成一致。
2. 如仍有理解偏差，再补一版低保真线框图。
3. 若线框图方向稳定，再决定是否进入最小可运行原型或正式实现计划。

## 10. 下一步建议

- 如果团队认可本说明，下一步建议先补线框图或用文字继续细化 4 个状态的布局草图。
- 若对“保留外部执行控件”仍有分歧，再回到交互方案草案，重新比较方案 A 与方案 B。
- 在侧边栏原型结论稳定前，`P8` 继续保持延期。
