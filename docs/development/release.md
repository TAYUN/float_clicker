# Float Clicker 构建与发布检查

本文档记录当前项目的打包、发布前检查和回滚建议。

目前项目仍处于功能开发阶段，暂未建立正式发布流程。本文档先作为 debug 包和阶段验收检查清单使用。

## 1. 当前发布状态

- 应用版本：见 `pubspec.yaml` 的 `version` 字段。
- 当前重点：单点模式稳定回归，多点模式分阶段开发。
- 正式渠道发布流程：待补充。

## 2. Debug 构建

构建 debug APK：

```powershell
flutter build apk --debug
```

构建前建议运行：

```powershell
flutter analyze
flutter test
```

交付前建议补充：

```powershell
git diff --check
```

Codex/AI 可使用 Float Clicker verify MCP 辅助执行 debug 验证流水线，但发布和阶段交付检查仍以这些原子命令为团队基线。没有注册 MCP 的成员应直接运行等价命令。

## 3. 阶段交付检查

每个多点阶段完成前检查：

- `git status --short` 中没有意外文件。
- 相关需求文档已更新。
- `docs/开发计划/多点模式开发阶段管理.md` 已更新任务状态。
- 自动测试或静态检查已运行。
- 无法自动验证的内容已列出手动验收项。
- 如果涉及单点共享逻辑，已说明单点回归情况。

## 4. Android 权限类功能检查

涉及悬浮窗或无障碍能力时，发布前至少确认：

- 悬浮窗权限未开启时，App 有明确提示。
- 无障碍服务未连接时，任务不会静默失败。
- 执行中关闭无障碍服务，任务能安全停止。
- 悬浮窗权限撤销后，悬浮组件能移除或进入安全状态。
- 横竖屏切换后悬浮组件仍保持可见。

## 5. 版本发布前待补充

正式发布前还需要补充：

- 版本号规则。
- release 签名配置。
- release APK/AAB 构建命令。
- 发布前完整验收清单。
- 崩溃日志和用户反馈收集方式。
- 回滚方案。

## 6. 回滚建议

当前阶段以 Git 回滚为主：

- 每个阶段尽量独立提交。
- 不把文档、模型、Android Overlay、调度器大改混在一个提交里。
- 多点开发期间，单点稳定性修复应单独提交，便于回滚和 cherry-pick。
